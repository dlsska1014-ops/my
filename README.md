# 똑똑한 가계부 V22.8.56 홈 HTML 예산 개정

V22.8.55 마크업 축소 실측을 근거로, 개인 홈 HTML 성능 예산을 측정 조건과 함께
다시 정의한 패키지입니다. 애플리케이션 동작(`src/index.js`)은 변경하지 않습니다.

## 이번 단계

- `AGENTS.md` 성능 예산을 측정 조건별 두 값으로 개정
  - 기준 픽스처(당월 6행) 35KB 이하 — 기존 값 유지
  - 실사용 부하(당월 200행, 피드 카드 10장) 44KB 이하 — 신규
- 근거: V22.8.55 축소 후 실측 42.5KB(43,542바이트), 여유 약 1.4KB
- 검증의 44KiB 상한을 임시 래칫에서 **문서화된 예산**으로 승격
- `BASELINE.md`·`RELEASE-CHECKLIST.md`의 예산 문구를 측정 조건과 함께 정리
- `src/index.js` 변경 없음, 총 1,149개 자동검사 통과
- 신규 SQL·Supabase 스키마·환경변수·Secret·Kakao Developers·OpenBuilder 변경 없음

## 개정 근거

35KB는 V22.8.10 시절 6행 픽스처에서 정한 값입니다. 피드 카드가 6장뿐인 조건이라
실사용 데이터에서는 처음부터 지킬 수 없는 값이었고, 검증도 같은 픽스처만 측정해
이 사실을 4라운드 동안 잡지 못했습니다.

| 당월 거래 수 | 피드 카드 | 홈 HTML |
| ---: | ---: | ---: |
| 6건 (기준 픽스처) | 5장 | 33.3KB |
| 50건 | 10장 | 42.6KB |
| 200건 | 10장 | **42.5KB** |
| 400건 | 10장 | 42.5KB |
| 3,200건 | 10장 | 42.5KB |

피드가 10장으로 고정되므로 크기는 50건 이후 평탄합니다. 무한 증가가 아니라
**측정 조건이 두 개**인 것이 실제 구조이며, 예산도 그렇게 정의했습니다.

## 남은 과제

- `/app` DB 호출 9회 예산 — 대량 월에서 18회. 집계 질의·RPC 설계가 필요하며
  `AGENTS.md`가 근거 없는 SQL 추가를 금지하므로 실행 계획을 포함한 별도 승인이 선행됩니다.
- `/skill` 호출자 인증 — `botUserKey`는 만료·회수 수단이 없습니다. Kakao
  OpenBuilder의 커스텀 헤더 지원 여부 확인이 선행되어야 합니다.

자세한 내용은 `KNOWN-ISSUES.md`와 `PERF_A11Y_AUDIT_REPORT_V22_8_53.md`를 확인하세요.

운영 Supabase의 V22.8.46 참여자 역할 SQL은 이미 적용된 상태를 전제로 합니다.
