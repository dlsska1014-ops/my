# 말해가계부 공개 콘텐츠 개선

## 확인한 문제와 개선 방향

2026년 10월 11일 AdSense의 `malhaebook.com` 사이트 상세 화면에서 `복제된 콘텐츠가 있는 화면에 Google 게재 광고`와 `가치가 별로 없는 콘텐츠`를 확인했습니다. ads.txt는 승인 상태였습니다. Google이 문제 URL이나 복제 원문을 제시하지 않았으므로 특정 문장이나 URL을 거절 원인으로 단정하지 않습니다.

기존 공개 안내는 짧은 기능 요약이 대부분이었고, 공동방 첫 기록 정책과 예산 입력 설명이 현재 구현과 달랐습니다. 공개 별칭 12개는 같은 문서를 200으로 반환했고 사이트맵의 수정일은 7월에 고정되어 있었습니다. 별칭의 존재는 검색 정리 대상이라는 근거이며 Google의 복제 판정을 입증하는 근거는 아닙니다.

[Google의 독창적인 콘텐츠 안내](https://support.google.com/adsense/answer/10015918?hl=ko)와 [복제 콘텐츠 정책](https://support.google.com/publisherpolicies/answer/11190248?hl=ko)에 맞춰, 실제 서비스에서 수행할 수 있는 작업과 검증 가능한 계산 예제를 중심으로 공개 안내를 다시 작성했습니다. 문서 수나 글자 수를 승인 기준으로 가정하지 않습니다.

## 적용한 개선

| 영역 | 변경 내용 | 검증 근거 |
|---|---|---|
| 공개 안내 18개 | 기존 14개를 보완하고 사용 가이드, 가상 체험, 리포트, 가져오기 안내를 추가했습니다. | 각 페이지의 고유 제목·설명·본문·링크를 검사합니다. |
| 예산 체험 | 실제 데이터 없이 분류 예산과 예산 밖 지출을 계산합니다. | 실제 `budgetSummary`와 여섯 조건을 비교하고 미설정·입력 오류·초기화를 확인합니다. |
| 원본 해설 | 255,000원 거래 예제, 120,000원 공동 정산, 같은 기간 비교와 가져오기 실패 대응을 설명합니다. | 저장소 구현과 계산식을 대조했습니다. 가상 사례임을 명시합니다. |
| 사실관계 | 공동방 생성·참여, 지출과 예산 명령 구분, CSV 복구 범위, 카드 사용액의 한계를 바로잡았습니다. | 기존 그룹·예산·가져오기·리포트 구현을 근거로 삼았습니다. |
| 운영 투명성 | 실제 운영자, 수정일, 문의 방법, 거래 원문과 오류 표본의 처리 범위를 표시합니다. | 존재하지 않는 이메일·후기·사용자 수·상담 기능을 만들지 않았습니다. |
| 탐색 | 목적별 가이드, 목차, 관련 글, 모바일 메뉴와 표의 가로 스크롤을 제공합니다. | 390px·1280px에서 18개 페이지를 확인합니다. |
| URL 정리 | 기존 별칭 12개와 공개 문서의 끝 슬래시는 308로 정본에 연결합니다. GET·HEAD 헤더를 일치시킵니다. | 고정 리디렉션 대상, 검색 매개변수 보존, 본문 없음과 링크를 검사합니다. |
| 검색 메타데이터 | 정본 URL·구조화 데이터·표시 수정일·사이트맵 수정일을 일치시킵니다. | 사이트맵에 정본 18개만 포함합니다. |
| 운영 화면 | HTML 응답의 기본값은 `X-Robots-Tag: noindex, nofollow`이며 공개 가이드만 명시적으로 색인을 허용합니다. | 기존 운영·로그인·명령 안내는 계속 열리며 검색 지시만 달라집니다. |

검색 제외는 접근 제어가 아니며 AdSense 정책을 우회하는 수단도 아닙니다. 기존 인증과 robots.txt의 비공개 경로 제한을 유지합니다. robots.txt로 차단된 경로는 크롤러가 noindex 헤더를 읽지 못할 수 있으므로 즉시 검색에서 사라진다고 주장하지 않습니다. [Google의 noindex 설명](https://developers.google.com/search/docs/crawling-indexing/block-indexing?hl=ko)을 참고합니다.

## 보호 범위

실제 거래·가계부·계정·권한·카카오 처리·SQL·환경변수·Secrets·불변 자산은 바꾸지 않습니다. 기존 `/my`·`/app` 호출 수 및 HTML 크기, 고정 분석 화면의 보호 검사를 유지합니다. 공개 체험은 서버 전송·쿠키·브라우저 저장소를 사용하지 않으며 새로고침하면 초기화됩니다. 광고 코드는 활성화하지 않고 사이트 소유 확인 메타 태그와 ads.txt를 유지합니다.

개인정보 안내는 거래 입력 원문, 임시 메모리 오류 표본, 설정에 따른 마스킹 표본 보관을 구분합니다. 기존 시행일을 새 날짜로 바꾸지 않습니다. 실제 운영·법적 의무를 전부 감사했다는 의미는 아닙니다.

## 적용과 재심사 순서

1. 최종 소스와 문서의 검증 결과를 `VERIFICATION_V22_9_39.md`에서 확인합니다.
2. 별도로 승인된 Git 게시 절차와 Worker 업로드·대조·승격 절차를 수행합니다. 전체 소스의 해시와 기존 바인딩·런타임을 대조합니다. SQL이나 외부 설정 변경은 필요하지 않습니다.
3. 운영 `/health`, 18개 공개 페이지, 별칭, sitemap.xml, robots.txt, ads.txt, 모바일 체험을 확인합니다. 로그인·실제 거래 저장은 별도 실계정 확인 범위입니다.
4. 운영 반영이 확인되면 AdSense → 사이트 → malhaebook.com에서 수정 확인과 재검토 요청을 진행합니다. 재검토 요청은 아직 제출하지 않았습니다.
5. Google이 다시 제시하는 상세 사유를 확인해 후속 조치를 결정합니다. 승인 여부와 처리 기간은 Google의 판단이며 이 변경으로 보장하지 않습니다.

로컬 검토는 `npm run preview:public`을 실행한 뒤 `http://127.0.0.1:4399/`에서 할 수 있습니다. 이 서버는 공개 페이지 검토 전용이며 로그인·실제 거래 기능은 열지 않습니다.
