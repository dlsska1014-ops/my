## 2. 발견한 문제 (우선순위순)

### P0. "먹통처럼 보임"과 "스킬 에러"의 공통 원인 — 직렬 DB 왕복

한 요청 안에서 Supabase 호출이 **거의 직렬**로 이어진다. 호출 하나에 40ms 지연을 넣어 잰 결과:

| 화면 / 발화 | DB 호출 | 동시 실행 최대 | 직렬 깊이 |
|---|---|---|---|
| `/app` 홈 | 11 | 5 | ~10 |
| `/budgets` | 11 | 2 | ~12 |
| `/my/settings` | 9 | **1 (완전 직렬)** | ~11 |
| `/reserve-plans` | 11 | 3 | ~11 |
| `/reports` | 13 (같은 거래 조회 2회 중복) | 5 | ~7 |
| 카카오 "커피 4500" (기록) | 14 | 2 | ~12 |
| 카카오 "수정 01번 금액 6만원" | 21 | 4 | ~18 |
| 카카오 "안녕" (이해 실패 응답) | 9 | 2 | ~9 |

- 모든 화면이 `user_security → users → household_members → households` **4단 직렬 인증 체인**으로 시작한다. 여기까지 4 RTT 를 쓰고 나서야 화면 데이터를 읽는다.
- Supabase 왕복이 100ms 면 홈은 서버에서만 1초, 카카오 기록은 1.2초, 수정은 1.8초다. 워커 콜드스타트·DB 지연이 겹치면 **카카오 스킬 5초 제한을 넘겨 "스킬 에러"** 가 나고, 웹은 HTML 이 `no-store` 라 화면 전환마다 흰 화면을 기다린다.
- 카카오 경로는 발화마다 `ensureUser → flow state 조회 → flow state 저장(POST) → 가계부 목록 → 선택 가계부 → 가계부 행 → 키워드 → 결제수단 → 분류` 를 **매번** 다시 읽는다. 수정 명령은 flow state 를 두 번 읽고 두 번 쓴다.

### P1. 기본 가계부가 "가장 최근에 만든/참여한 가계부"로 잡힌다

`fetchUserHouseholds` 가 `created_at.desc` 로 정렬하고, `getMySelectedHousehold` 는 `household_id` 가 없으면 `households[0]` 을 고른다.
픽스처(생활비 + 나중에 만든 여행 가계부)에서 `/my` 로그인 직후, `/my/settings`, `/reserve-plans`, `/menu` 를 주소로 직접 열면 **여행 가계부**가 열린다.
홈 안의 링크는 `household_id` 를 달고 있어 괜찮지만, 로그인 직후·북마크·카카오 링크 진입에서는 "왜 다른 가계부가 뜨지"가 된다. 웹에는 카카오의 `kakao_selected_household` 같은 "마지막에 쓰던 가계부" 기억이 없다.

### P1. 검증 하네스가 환경에 따라 다르게 판정된다

- Windows CRLF (오늘 수정), 날짜 의존 검사 (오늘 수정), CI 는 ubuntu 단일.
- 검사가 `new Date()` 를 직접 읽는다. 서버에 고정 시계 주입 수단이 없어 월말·연말 검사가 재현 불가.

## 3. 개선 방향

### 1단계 — 느림과 스킬 에러를 잡는다 (구조 변경 없이, 가장 먼저) — **V22.9.16 에서 처리**

> 결과: 홈 11회/10단계 → **8회/3단계**, 예산 12단계 → 3단계, 설정 11단계 → 3단계, 카카오 기록 14회/12단계 → **12회/6단계**, 수정 21회/18단계 → 17회/11단계. 인증 사슬은 RPC 대신 PostgREST 자원 포함(외래키)으로 줄여 SQL 없이 끝냈다. 상세는 `CHANGELOG.md` V22.9.16, 회귀 검사는 `validation/validate-serial-depth-v22916.mjs`.

1. **인증 체인 1회 RPC 화**: `accountbook_session_context(user_id)` 하나가 `user_security + users + household_members + households` 를 돌려주게 하고 `verifyUserSession`/`getMySelectedHousehold` 가 그 결과를 쓴다. 4 RTT → 1 RTT. (SQL 1건 필요 — 승인 후 적용)
2. **화면 데이터 `Promise.all`**: `/my/settings`, `/budgets`, `/reserve-plans` 처럼 서로 독립인 조회를 한 번에 던진다. `getSettingValue` 는 요청 단위로 묶어(`key=in.(...)`) 한 번에 읽는다 — 홈은 이미 그렇게 한다.
3. **카카오 프리앰블 통합**: 발화마다 반복되는 `ensureUser → flow → 선택 가계부 → 가계부 행 → 키워드/결제수단/분류` 를 한 함수·한 병렬 묶음으로 만들고, flow state 는 필요할 때만 쓴다. 목표: 기록 14→6 호출, 깊이 12→4.
4. **중복 제거**: `/reports` 거래 조회 2회 → 1회.
5. **관측 추가**: `/skill` 은 이미 `handlerStartedAt` 을 잰다. 응답 시간 p95 와 DB 호출 수를 `/health` 에 노출하고, 4초를 넘긴 발화는 `rememberOpsEvent` 로 남긴다. 고치기 전후를 숫자로 비교한다.

측정 기준: 위 표의 "직렬 깊이" 를 홈 ≤4, 카카오 기록 ≤5 로 내린다. 픽스처 계측 스크립트로 회귀 검사에 넣는다.

### 2단계 — 동작 결함 — **V22.9.17 에서 처리**

> 결과: 마지막 가계부는 브라우저 쿠키 `ab_hh` 로 기억(낡은 쿠키는 고르기 화면 + 삭제, 로그아웃 시 삭제, DB 왕복 증가 0). 카카오 수정 응답 금액 `60,000원`, 인사 발화는 인사로. 검증 전용 고정 시계 `globalThis.__AB_QA_FIXED_NOW_MS`. 회귀 검사는 `validation/validate-last-household-memory-v22917.mjs`.

1. **마지막에 쓰던 가계부 기억**: 웹도 `last_household:{user}` 설정(또는 서명 쿠키)을 두고 `household_id` 가 없을 때 그 값을 우선한다. `/my` 리다이렉트·`/menu`·`/my/settings`·`/reserve-plans` 가 모두 같은 규칙을 쓴다. 없으면 지금처럼 첫 가계부.
2. 카카오 수정 응답 금액 표기 통일(`60,000원`), "안녕/고마워" 류 인사 발화는 이해 실패가 아니라 짧은 인사 + 다음 행동 안내로.
3. 서버 시계 주입(`env.QA_FIXED_NOW` 같은 검증 전용 값)으로 월말·연말 검사를 재현 가능하게.

### 3단계 — UI/UX

1. **실기기 스크린샷 기준 점검을 먼저** 한다(아래 "확인 못 한 것"). 구조 계측만으로는 겹침·잘림·대비를 판정할 수 없다.
2. 홈 밀도 축소: 드로어 23개 링크는 "자주 쓰는 6개 + 나머지 접기" 로, 최근 내역의 행마다 붙은 수정/삭제 접기는 행 탭 → 상세 시트 하나로.
3. CSS 다이어트: 셸 CSS 189 KB 를 "공통 셸 + 화면별 CSS" 로 나눠 홈 첫 로드를 절반 이하로. `!important` 986개는 컴포넌트 클래스로 옮기며 화면 단위로 줄인다(한 번에 전량 치환 금지 — `CLAUDE_DIRECTION.md` 원칙 유지).
4. 첫 로드 체감: 서버 응답 전까지 흰 화면이 아니라 셸(상단 바·탭)이 먼저 그려지도록 셸 HTML 을 앞쪽에 두고 데이터 블록만 뒤에 붙인다.

### 4단계 — 저장소 위생

1. 루트의 판별 문서·스크립트를 `docs/history/` 로 옮기고 최신 3판만 루트에 둔다. 체크섬 매니페스트는 현재 1개만 쓴다.
2. `README.md` 를 현재 판(V22.9.15) 기준 "무엇을 어디서 읽나" 로 다시 쓴다.
3. CI 에 `windows-latest` 잡을 추가해 CRLF·경로 문제를 잡는다.

## 4. 확인 못 한 것

- **브라우저 실화면**: 픽스처 서버를 Chrome 으로 열려 했으나 샌드박스 네트워크 격리로 연결이 거부됐고, 격리를 푼 실행은 권한 정책에 막혔다. 겹침·잘림·대비·터치 반응은 실기기(또는 사용자가 직접 띄운 로컬 서버)로 봐야 한다.
- **운영 DB 지연 실측**: 위 표의 깊이는 호출당 40ms 가정이다. 실제 Supabase 왕복 시간을 `/health` 에서 재면 1단계 효과를 정확히 예측할 수 있다.
- **카카오 오픈빌더 설정·`KAKAO_SKILL_SECRET`**: 헤더 없이 켜면 즉시 403 이 난다(`00_READ_FIRST_V22_8_76.md`). 운영 콘솔은 보지 않았다.
