# 남은 운영 항목의 분류와 추천 방향

이 문서는 V22.9.29 준비 상태이며 배포 완료로 오인하지 않습니다.

| 항목 | 구현/추천 | 외부 상태 |
|---|---|---|
| 29~31일 | 지정일 보존, 짧은 달만 말일, 최소 RPC 정의 패치 | SQL 승인·적용 후 Worker 배포 |
| blocked/viewer/pending 참여 | 실제 권한별 안내, 차단에는 성공·선택 상태 없음 | 가상 웹·회귀 확인, 실계정 별도 |
| 50건 검색 | 51번째 조회로 초과 여부·표시 한도 공개 | 새 검색·V5·목표 자산 주소 배포 필요 |
| 무한 DB 조회 | Supabase GET·HEAD 10초, 공식 metrics 기존 8초 유지 | 쓰기 새 강제 취소는 보류 |
| 불명확한 쓰기 | typed unknown·원인 체인 보존, 확정 재조회, 불확실한 보상 삭제·맨몸 재생성 금지 | 모사 실패/늦은 커밋 확인 |

| 스킬 인증 헤더 | 등록 키 200·오류 키 403, 기존 설정 유지 | 실제 카카오 앱 확인 별도 |
| CPU/Max Rows/Billing | 현행 운영 값과 관측 후 필요할 때만 최소 변경 | 유료 변경·새 Secret은 별도 승인 |
| 실제 카카오/OAuth/실기기 | 테스트 절차 유지, 소스 검사와 구분 | 사용자·실기기 수동 확인 |

## 과거 기록
SQL 패치는 함수 정의만 바꾸며 과거 거래나 last_applied_month를 바꾸지 않습니다. 지정일 31은 다음 달에도 31로 유지합니다. 이미 같은 월에 반영한 거래를 재반영하거나 28일 거래를 추정 이동하지 않습니다. 기존 관리자 저장이 원래 지정일을 28로 잘라 저장한 경우 사용자 의도 확인 없이 복구할 수 없습니다.

## 잠금의 한계
DB 협력 lease·정렬된 사용자 잠금·가계부 잠금·재조회는 정상 애플리케이션 writer 사이를 보호합니다. 직접 SQL·외부 service-role writer는 우회할 수 있고 만료 전에 발행한 원격 쓰기가 늦게 커밋하는 경계는 완전한 DB fencing이 아닙니다. 무조건 안전하다는 표현 대신 불명확 상태에서 쓰기 반복·삭제 보상을 하지 않는 방향을 유지합니다.
