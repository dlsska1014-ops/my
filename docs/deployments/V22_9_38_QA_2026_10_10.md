## 카카오 로컬 연속 검증

저장소 밖 `review-artifacts/v22938-functional-qa/verify-kakao-local.mjs`에서 배포본과 같은 `src/index.js`의 실제 `Worker.fetch`를 호출했습니다. 사용자·가계부·로그인 키·Secret은 모두 가상 값이며 메모리 저장소만 사용했습니다. 허용한 모의 저장소와 OAuth 응답 이외의 외부 fetch는 차단하고, `waitUntil` 작업도 끝날 때까지 수집했습니다. 실제 카카오 요청이나 운영 DB 쓰기는 없습니다.

독립 검토에서는 HTML 전체에서 `200원`을 검색하면 다른 거래의 `1,200원`에도 일치하는 검증 코드의 문제가 발견됐습니다. 거래 ID에 해당하는 카드가 정확히 한 개이며 그 카드의 지출 금액이 `-100원` 또는 `-200원`과 정확히 일치하는지 대조하도록 보완했습니다. 삭제 뒤에는 해당 카드가 없어야 합니다. 보완 후 두 모드에서 각각 135개 단언이 다시 통과했습니다.

재현 명령은 `node ../review-artifacts/v22938-functional-qa/verify-kakao-local.mjs`와 같은 명령에 `--categories-absent`를 붙인 형태입니다. 저장소 루트에서 실행하며 결과는 `kakao-local-present.log`, `kakao-local-absent.log`에 있습니다. 이 추가 검사는 기존 배포 묶음의 9,591개 검사와 별도로 집계합니다.

## 입력 과정에서 확인한 주의점

날짜·시각 숫자가 들어간 테스트 카드 별칭은 카드번호 보호 규칙이 거절했습니다. 숫자가 없는 별칭으로 재입력할 때 오류 후 기본 종류로 돌아간 것을 놓쳐 처음에는 입출금·통장으로 등록했습니다. 같은 테스트 자산을 상세 수정하여 신용카드로 바꾸고 화면의 종류를 확인한 뒤 목표 검증을 진행했습니다. 별도 자산을 중복 생성하지 않았습니다.

Aside 지시문에는 숫자가 없는 별칭과 오류 후 모든 필드를 재확인하는 절차를 반영했습니다. 이 폼 초기화는 테스트 준비 중 관찰한 UX 사항이며, 카드 목표 저장 결함으로 분류하거나 소스를 임의 수정하지 않았습니다.

## 남은 검증과 다음 단계

- 거래 삭제는 완료됐습니다. 삭제를 다시 실행하거나 같은 대상 거래를 재생성하지 않습니다. 현재 10월은 **3건·지출 1,400원·수입 1,000원**, 모든 달 합계는 4건·지출 1,500원·수입 1,000원입니다.
- 계정 B의 실제 브라우저 참여·역할별 UI는 미실행입니다. 같은 권한 경계는 위 로컬 시나리오에서 확인했습니다. 실제 A 세션은 로그아웃했으며 다시 필요한 경우 사용자가 기존 비밀번호로 로그인해야 합니다.
- 카카오 실제 참여 요청을 기다리지 않습니다. 사용자가 코드 검증으로 전환했으므로 기존 카카오 계정에 로그인·참여·선택 변경을 수행하지 않았습니다. 로그아웃 전 테스트 가계부 참여자는 A 한 명이었습니다.
- 실제 카카오 메시지, OAuth 공급자 콜백, 실발급 웹 연결 코드는 미실행입니다. 위 로컬 모의 공급자·가상 코드의 통과와 구분합니다. A에 실제 카카오 로그인 식별자를 연결하지 않았습니다. 사용자가 나중에 실환경 검증을 요청하면 Aside 절차를 적용합니다.
- 실제 iPhone·Android·인앱·VoiceOver·TalkBack·한글 IME·복사 거절 경로는 미실행입니다. PC 키 입력을 실기기 통과로 간주하지 않습니다.
- 테스트 가계부에 정기 규칙이 없어 정기 항목 편집은 미실행입니다. 운영 cron이 실행할 활성 규칙을 만들지 않았습니다. 실제 조회 장애·동시 수정 충돌·DB 감사 행·물리 삭제도 이번 결과로 증명되지 않습니다.

[Aside 지시문](../ASIDE_V22_9_38_FUNCTIONAL_QA.md)에 기기별 순서·예상 결과·중단 기준·기록 양식이 있습니다. OAuth 로그인 식별자 연결과 1회용 웹 연결 코드는 다른 경로이며 하나의 통과로 다른 하나를 대신하지 않습니다.
