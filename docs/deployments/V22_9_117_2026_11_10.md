## 설계
- 같은 카카오 id 면 예전 그대로(확인 모드는 그 id 의 주인 = 제안의 웹 계정도 본다).
- 다른 카카오 id 면 로그인 콜백(mode login)은 합치기 표를 주지 않는다(other_login_needs_confirm). /my 가 확인 화면을 보이고, 단추를 누른 뒤(mode confirm)에만 셋 다 맞을 때 받는다.
  - ① 방금 확인한 카카오 id 의 주인(lookupKakaoLoginOwner = 강한 식별 → 링크 표 `kakao_login:<id>` → 사용자 키, 합친 계정은 resolveEffectiveUserId 로 따라감)이 제안의 웹 계정.
  - ② 방금 확인한 카카오 id 와 제안의 카카오 id 가 둘 다 그 웹 계정의 ‘믿는 카카오 로그인’(kakaoAccountLinkOtherLoginTrustedV229117). 믿는 카카오 로그인 = 강한 식별(fetchStrongIdentityForUser) + 링크 표에서 그 웹 계정을 직접 가리키는 provider kakao_login 별칭(옛 웹 카카오 로그인만 썼고 지금 코드는 쓰지 않음).
  - ③ 그 집합에서 해시가 제안 해시와 같은 id 의 주인을 같은 순서로 다시 읽어 그 웹 계정인지.
- 믿지 않는 것: 사용자 키(users.kakao_user_key), provider skill(단톡방 요청)·identity_merge(관리자 통합·계정 잇기) 별칭. 위조 요청으로 만들 수 있다(V117:L-5·L-6). 한 계정의 강한 식별은 하나뿐이라, 위조로 만든 계정은 두 카카오 id 를 다 믿는 자리에 둘 수 없다.
- 확인 표(`ab_account_link`, 5분)의 h 는 제안의 해시, c 는 제안의 방 기록 계정이다. `/my/account-link/run` 은 h·c 와 세션 사용자(제안의 두 쪽 중 하나)를 대조한다(L-8). 방금 한 카카오 확인 없이 세션 쿠키만으로는 여전히 못 잇는다.
- 화면: 화면 전용 CSS(KAKAO_ACCOUNT_LINK_PAGE_CSS)·테마 스크립트, 오류는 제목 바로 아래(role=alert), 두 계정 줄 두 줄, 문구 고침, 오류 이름은 Object.hasOwn(L-11). `kakao_account_mismatch`·`kakao_offer_unverified` 화면에서 보통 브라우저(인앱 아님)는 hidden relogin=1 + 단추 ‘다른 카카오 계정으로 확인하고 잇기’ + 안내 한 줄 → 카카오 시작이 prompt=login(인앱은 prompt=none 그대로 + 인앱 안내 한 줄, 카카오 문서: 인앱은 prompt=login 없음).
