# 사용자 가져오기 선행 계약

구현 범위는 /my/backup → /my/import입니다. 관리자 백업 감사·D 열 연결 UI·C 비교 그래프·정기 실행·운영 변경은 포함하지 않습니다.

## 권한과 원본

미리보기와 저장은 현재 가계부의 기록 가능한 제출자와 지출자만 허용합니다. 잠금 이후의 현재 owner/admin만 타인 지출자를 저장할 수 있습니다. 강등·탈퇴·제한된 지출자를 다른 사람으로 대체하지 않습니다. 새로 분석하는 member와 기록만 구성원은 본인 거래를 저장할 수 있습니다.

클라이언트는 input_source=file/text/converted와 input_revision을 명시합니다. Excel 원본과 그 TSV는 같은 리비전의 한 원본입니다. 전달 시 선택하지 않은 표현은 multipart에서 제거합니다. 표식 없이 파일과 텍스트가 함께 있으면 충돌로 거절합니다. CSV의 ms-excel MIME만으로 바이너리로 보지 않으며 실제 바이트 서명·디코딩·제어 문자·크기 검증은 유지합니다.

## 날짜·열·위치

직접 파서의 importYear 단독 지정과 기존 HTTP month는 명시한 연도입니다. 새 HTTP 폼은 현재 기본 기준과 선택한 연도를 구분합니다. 유일한 명시 연도를 가진 파일은 그 연도를 우선하며, 현재 기본 기준의 월일만 183일 규칙으로 보정합니다. reference_date/year/mode/file_year는 서명 토큰의 parsed.date_basis로 보존합니다. previous_import_token은 현재 사용자·가계부·원본 해시·만료를 검증하고 같은 기준일·jti를 재사용합니다. 기준을 명시적으로 바꾸면 새 미리보기를 확인합니다.

시간 전용 열은 날짜 열을 대신하지 않습니다. 괄호·대괄호 단위와 KST/UTC 접미어가 붙은 시간 열에도 같은 규칙을 적용하며 날짜+시간 열은 유지합니다. 제목 표는 유효 필드만 추론에 사용하며 제외/보조/raw_text는 보존 원문에만 남깁니다. 명시 분류·결제수단은 사용자 값을 유지하고 80자/제어 문자 검증을 위반하면 확인 이유를 표시합니다. 기존 음수 지출의 환급 분류 전환은 보호합니다. 통화와 외화 금액 보호는 유지합니다.

row_number는 내부 논리 레코드 ID이며 고정 거래 ID·selected_rows의 입력입니다. source_location은 물리 시작/끝 줄·논리 레코드·표 구간을 분리하여 화면에 표시합니다. 빈 줄이나 셀 안 줄바꿈으로 표시 줄이 달라져도 내부 ID는 표시 번호를 사용하지 않습니다.

## 중복과 한도

기본 대응은 가계부·날짜·유형·금액이 같고 정규화한 원문이 같거나 분류/메모/결제수단이 모두 같은 거래입니다. 제출자 user_id는 필수 조건이 아닙니다. 파일에서 정확히 연결한 실제 지출자가 명시되어 있으면 그 실제 지출자도 대응 조건입니다. 따라서 다른 구성원이 같은 명세서를 제출하는 보호와 명시적 실제 지출자가 다른 두 거래의 구별을 함께 유지합니다.

각 기존 DB 행은 한 파일 발생에만 소비합니다. 소비한 DB ID를 duplicate_basis로 서명하고 파일의 순서/논리 ID를 유지합니다. commit은 그 ID와 전체 ready의 고정 ID를 예약한 뒤 새로 생긴 다른 토큰의 거래만 추가 소비합니다. 같은 토큰의 형제 행을 다시 소비하지 않아 역순 부분 선택도 보존됩니다. 선택한 일부 행만 대응하지 않고 전체 ready 순서에서 외부 거래를 배정한 뒤 선택을 적용합니다. skip_duplicates=false는 명시적 동일값 추가를 허용하지만 같은 토큰의 고정 ID는 유지합니다.

기본 120건은 중복 뒤 새 후보에 적용합니다. 금액 500개 묶음·기간 필터와 exact count/페이지로 전체성을 확인하며 짧은 서버 페이지에서도 실제 길이로 다음 페이지를 읽습니다. count 부재·실패·빈 중간 페이지·32회 조회 또는 40,000 후보의 보호 한도는 중복 없음으로 처리하지 않습니다. 요청 전체 50회 예산의 나머지 호출을 예약합니다.

고정 ID와 같은 jti의 source_user_key 조회는 금액·날짜 필터와 분리합니다. 저장 후 금액·날짜·ID·source key가 변경되어도 실제 저장 필드를 비교하여 충돌을 알리고 쓰기 RPC를 호출하지 않습니다. 이 조회에도 exact count·페이지 완전성·요청 예산을 적용합니다.

같은 jti를 유지한 후속 분석은 원본의 기존 5,000 논리 행 범위에서 누적될 수 있습니다. 이 이름 공간의 조회 보호는 5,000행이며 1회 저장 상한 1,000건과 구별합니다. 기본 저장은 계속 120건이고 입력·파싱·저장 한도를 높이지 않습니다.

## 불명확한 저장

기존 transaction-import 가계부 잠금과 원자적 RPC를 사용합니다. 기존 설정 표의 my_import_source_v22955 키에는 원문 없이 원본을 구분하는 해시·jti·고정 거래 ID·저장값 해시·상태·32자리 고유 리비전만 둡니다. 해당 원본의 pending 상태는 새 분석·새 토큰/ID를 막습니다. 같은 토큰의 원래 행·값·ID만 재시도하며, 모든 해당 ID의 실제 저장값이 일치할 때만 상태를 해제합니다. 현재 행의 부재나 재시도의 확정 거절만으로 이전 요청 실패를 추정하지 않습니다. preview는 상태를 바꾸지 않으며, 저장 상태 변경은 잠금의 유효 기간과 이전 리비전 접두어의 조건부 일치를 함께 검사합니다. JSON 전체를 조건 URL에 넣지 않습니다. 늦은 확인 쓰기가 새 pending 상태를 덮어쓰지 않습니다. 다른 내용으로 바꾼 원본까지 같은 요청으로 식별하는 기능은 없습니다.

불명확한 저장의 기존 토큰이 만료되거나 사라지고 실제 저장값도 끝내 확인되지 않으면 이 원본의 새 분석은 계속 차단됩니다. 안전한 사용자 복구 경로는 후속 계약으로 남으며 상태를 임의로 초기화하지 않습니다.

## 상한·성능·복원 한계

기존 5 MiB 입력과 기본 5,000/최대 10,000 논리 행, 기본 저장 120건을 유지합니다. CSV는 4,096열·250,000 구분 셀에서 명시적으로 멈추고 JSON도 같은 구조 예산을 검사합니다. 처리하지 않은 구간은 분석 완료로 표시하지 않습니다. 이 구조 예산은 반복 계산을 감추기 위한 행 수 축소가 아니라 폭/셀 수에 따른 메모리 보호입니다. 최대 5 MiB의 단일 셀도 분석합니다.

고정 별칭은 최초 exact와 최장 fuzzy/동률 선언 순서를 유지하는 유한 인덱스입니다. 입력 제목/원문은 전역 캐시에 저장하지 않습니다. 날짜 포매터는 요청당 한 번이며 표 구간의 열 메타데이터를 재사용합니다. 성능 완료의 세 근거와 동일 입력 해시는 최종 보고서를 확인합니다. Node 결과를 운영 Cloudflare 10ms 통과로 주장하지 않습니다.

CSV 이스케이프 조각은 일정 개수마다 합칩니다. 공용 정규화의 마지막 기호·공백 처리는 작은 구간으로 나누되 같은 결과를 만들고, 분류는 전체 단어 배열 대신 정본 exact 단어의 경계만 확인합니다. 제목 표의 내용 열을 분류 문맥에 두 번 복사하지 않습니다. V53 불변 예산 자산에는 원래 직렬화한 정규화 함수를 보존합니다.

현재 사용자 CSV는 읽기 쉬운 내보내기이며 별도 raw_text가 없습니다. 명시 결제수단의 축약과 원문 필드의 불필요한 변경을 막았지만 완전 복원은 제공하지 않습니다. 수식 방지와 실제 작은따옴표를 유지합니다. 버전이 있는 원본 필드·복원 모드는 후속 파일 계약입니다.
