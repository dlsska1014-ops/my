# 변경안: 화면마다 다른 ‘월말 예상’을 한 기준으로 (V76:W-7, P2)

V22.9.78 에 넣은 **변경안**이다. 코드는 아직 바꾸지 않았다. DB 변경은 필요 없다.
2026-10-23 운영자 결정: 홈·예산 알림·리포트의 예측 기준과 기준일을 하나로 맞추고, 실제 금액과 예상 금액을 구분한다(별도 변경안).
경로는 `src/modules/` 를 뺐고, 줄 번호는 V22.9.78 작업 중(ee625ac) 기준이다.

## 먼저 정해 주실 것

1. 분류 예산을 쓰는 가계부에서 따로 보이는 ‘월말 예상’을 무엇으로 할까요?
   제안: 따로 보이는 숫자는 전체 지출로, 예산과 견주는 줄은 예산 분류만으로.
2. 준비금(정기지출 항목)의 남은 납부 예정액을 월말 예상에 넣을까요? 제안: 넣는다(홈 ‘앞으로 나갈 돈’과 같은 합이 된다).
   앞 날짜로 미리 적은 일반 지출은 지금처럼 예상에서 뺄까요? 제안: 뺀다(D3 계약 ‘미래 거래 추가 합산 안 함’).
3. ‘초과 예상’ 상태와 알림에 반영 대기 고정지출을 넣어도 될까요? 알림이 늘 수 있다.
   ‘하루 사용 가능’을 내림으로 통일해도 될까요(지금 홈은 내림, 알림은 반올림이라 1원 다르다 — V44 D-18)?
   ‘하루 사용 가능’에서 반영 대기 고정지출을 미리 뺄까요?

## 지금 어긋나는 점

기준일은 이미 하나다(서버 KST 오늘, 이번 달은 1일~오늘, 지난달은 그 달 전체, 미래 달은 관측 전). 어긋나는 것은 계산이다.

- **분류 범위**: 분석·리포트·스마트 도구·밈·위험 점수는 전체 분류, 예산 알림·알림센터·홈 하루 계획은 예산 분류로 계산한다.
- **고정지출**: 반영 대기·지정일 뒤 정기 기록은 예산 알림의 ‘가정값’ 줄에만 들어간다. 상태 판정·홈·분석에는 없다.
- **월초 고정지출이 속도로 부풀려짐**: 이미 적힌 월세도 ‘하루 평균 × 그 달 일수’에 섞인다.
  예: 예산 150만, 1일 월세 60만, 하루 2만씩, 오늘 10일(31일 달) → 지금 식은 248만으로 ‘초과 예상’, 실제 기대값은 122만(기록 80만 + 남은 21일 × 2만).
- **‘반영됨’ 판정이 세 가지**: 알림은 `last_applied_month`, 리포트는 `recurring:<id>:<달>` 표식 기록, 홈 ‘앞으로 나갈 돈’(W-5)은 둘 중 하나.
- 영수증 확인 여부, 반올림·내림도 곳마다 다르다.

계산하는 곳: `domain/analytics.js:169-184`(burnForecast), `features/budget-alerts-annual-goals.js:19-84`(예산 알림 모델),
`features/settlement-ops-pages.js:61-76`(/budget-alerts), `api/user-api.js:266-355`(알림), `my/mobile-home.js:177-206`(홈 하루 계획),
`my/home-sections.js:178-203`(앞으로 나갈 돈), `my/report-challenge.js:261-289`, `my/analysis-page.js:58·165`, `my/reports-premium.js:452-521·744`,
`features/meme-engine-premium.js:23·241`, 옛 관리자 화면 `admin/dashboard-fragments.js:31`·`admin/pc-analysis-calendar.js:305`.
`domain/analytics.js:247-254` forecastMonthlyExpense 는 부르는 곳이 없는 죽은 코드다. 예산 균등선(`client/insight-main.js:24-51`)은 예측이 아니라 그대로 둔다.

## 제안: 공통 함수 하나

새 파일 `domain/spending-outlook.js` 의 `monthSpendingOutlook({ month, rows, today, receipt, recurring, plans, budgets, scope })`.
W-5 의 대기 고정지출 규칙(`homeUpcomingOut`)도 domain 으로 옮겨 같은 이름으로 다시 내보낸다.

- 입력: 그 달 전체 행(앞 날짜·수입 포함). `recurring`·`plans` 가 null 이면 ‘못 읽음’. `scope: "budgeted"` 는 예산 분류 판정 함수 하나(`domain/budgets.js` 에서 내보냄)로 거른다.
- 출력: 상태(complete·before·unavailable), 기록(오늘까지·고정·변동·앞 날짜 포함 등록액), 아직 안 적힌 것(대기 고정지출·남은 준비금 납부·예산 밖 대기), 예상(합과 내역, partial), 예산(남은 액·하루 사용 가능·차이·바닥나는 날).

이번 달 식:

```
월말 예상 = 오늘까지 기록 + 오늘 뒤 날짜의 정기 기록 + 반영 대기 고정지출 + 남은 준비금 납부
          + round(오늘까지 변동 지출 ÷ 지난 날 수 × 남은 날 수)
```

- 정기 출처 행(source 가 recurring_auto·recurring 이거나 raw_text 가 `recurring:<id>:<달>`)은 속도 계산에서 뺀다. 월세가 부풀지 않는다.
- 앞 날짜의 일반 지출은 더하지 않고 따로 돌려준다(D3 계약).
- 규칙 ‘반영됨’ = `last_applied_month` 가 그 달이거나 그 달 표식 기록이 있음(W-5 와 같음). 한 번만 센다.
- 정기 행·준비금·대기가 없으면 지금 burnForecast 와 같은 값이 나온다.
- 규칙을 못 읽으면 대기 없이 계산하고 partial 로 표시한다(“고정지출을 읽지 못해 빼고 계산”).
- 지난달은 예상 = 실적, 미래 달은 관측 전, 영수증 불완전·날짜 오류는 unavailable.
- 기준일: 요청마다 서버가 오늘을 한 번 정해 모든 카드에 넘긴다. 10-31 23:59:59 KST 는 10월(남은 날 0), 11-01 00:00 KST(10-31 15:00 UTC)부터 11월.
- 하루 사용 가능 = floor(남은 예산 ÷ 오늘 포함 남은 날). 바닥나는 날도 같은 근거로 계산한다.

## 화면별로 바뀌는 것

라벨로 기록과 예상을 나눈다: “기록 N원”(오늘까지), “등록액 N원(앞 날짜 포함)”, “월말 예상 N원”, 내역 한 줄 “기록 A + 남은 고정·정기 B + 남은 n일 예상 C”. 지난달은 “실적”, 미래 달은 “관측 전”.

- **예산 알림 모델**: 예상과 대기 가정값을 하나로 합친다. ‘초과 예상’ 판정에 대기분이 들어간다. 문구 “남은 고정지출과 지금 속도를 더하면 월말에 예산을 넘을 수 있어요.” 카카오 안내도 같은 숫자.
- **/budget-alerts**: “관측 속도 월말 예상” → “월말 예상 지출” + 내역 줄. 가정값 줄은 합쳐지므로 지운다.
- **알림 JSON**: 키는 지우지 않는다. forecast 를 새 합으로, expected_parts 를 더한다. after_pending_assumption 은 한 판 동안 같은 값으로 둔다(저장소 안 소비처는 검사뿐, 밖은 확인 못 함).
- **홈**: “이 속도면 N원이 남습니다” → “월말 예상대로면 N원이 남아요”. 규칙·준비금은 이미 읽어 추가 요청 없음. ‘앞으로 나갈 돈’은 같은 함수의 결과를 쓴다(W-5 검사 52개 그대로 통과).
- **분석·리포트·스마트 도구·밈·위험 점수**: burnForecast → 전체 분류 예상. 부제 “현재 속도 기준” → “기록 + 남은 고정 + 남은 날 예상”. 리포트의 예산 비교 줄만 예산 분류로.
  /my/analysis 기본 화면은 규칙·준비금 읽기 +2, ?view=report·/smart-tools 는 준비금 +1(없다면).

## 적용 순서

1. domain 함수와 새 검사만(화면 변화 없음).
2. 예산 알림·알림센터(한 모델).
3. 홈 하루 계획·앞으로 나갈 돈(추가 요청 없음).
4. 분석·리포트·스마트 도구·밈·위험 점수(요청 추가).
5. 문구·안내·카카오 안내, 죽은 코드 정리.
6. 환불 연결(D-5·M-7, 별도 변경안)이 들어오면 차감 행을 연결한다: 기록에는 넣고 속도 계산에서는 뺀다.

## 위험

- ‘초과 예상’ 상태와 알림이 늘어난다(대기 고정지출 포함). 내역 줄로 이유를 보인다.
- 규칙 없이 월세를 손으로 적는 가계부는 여전히 속도로 부푼다(정기지출로 알아볼 표식이 없음).
- 준비금을 납부일 전에 일반 지출로 미리 적으면 납부일까지 두 번 센다(W-5 카드와 같은 한계, V78 S-1 참고).
- 알림 JSON 의 forecast 뜻이 바뀐다. 저장소 밖 소비처는 확인하지 못했다.
- /my/analysis 요청이 2개 늘어 지연·Free 플랜 CPU 부담. 홈 35 KiB 예산도 지켜야 한다.
- 옛 검사의 숫자·문구를 많이 고쳐야 한다. 바꾼 단언은 목록으로 남긴다.
