# V22.9.125 글자 크기·굵기 눈금, 위계, 밀도 (2026-11-15~16)

V22.9.124 의 UI/UX 기준 점검에서 ‘남긴 것’(V124:U-8~U-13)으로 적은 위계·밀도 문제를 사용자가 출시 전에 고쳐 달라고 했다
(2026-11-15 밤 “… 나머지도 배포 전 개선됬으면 좋겠는데 위계 밀도 그리고 전체적으로”).
운영 V22.9.124 코드(origin/main f05d0f8)의 화면 36곳(로그인 뒤 27 + 공개 9)을 헤드리스 Chrome 으로 390·768·1440 폭에서 다시 쟀다. 픽스처만 썼고 운영·DB 에는 닿지 않았다.
측정 도구와 전후 결과는 저장소 밖 `review-artifacts/v125-hierarchy-density-2026-11-15/audit/` 에 있다.

## 잰 결과 (고치기 전)

- 굵기: 글자 요소의 66%(390 폭)·65%(768)·70%(1440)가 600 이상이었다. 휴대폰 홈은 208개 가운데 177개(85%)가 600 이상, 91개(44%)가 750 이상.
  ‘예산 사용률’(12px·1000), ‘오늘 쓴 돈’(12px·850), ‘이대로면 월말에 …’(12px·800) 같은 보조 글자가 제목·금액과 같은 굵기였다. 굵기 값은 10가지(400~1000).
- 크기: 32~33가지(9~44px, 반 픽셀 포함). 11px 보다 작은 글자가 390 폭 203개·1440 폭 167개(데스크톱 사용 내역의 날짜·분류 10~10.5px, ‘원’ 9px, 공개 화면 꼬리말 10.5px).
- 규칙이 없어 브라우저 기본값이 쓰이던 곳: 단추 195개·small 160개가 13.33px.
- 밀도: 휴대폰에서 머리(달 이동 줄)와 첫 카드 사이 빈 띠 38px, ‘예산 사용률 20%’ 칩이 두 줄.
- 모서리: 홀수 값(9·11·13·15·17·19·21px)이 390 폭 286개·1440 폭 810개(사이드바 메뉴 11px 가 대부분).
- 그대로 0 이던 것: 가로 스크롤, 대비 미달(밝은·다크), 이름 없는 조작 요소, 움직임 줄이기 미적용.

## 정한 눈금과 역할

- 글자 크기 11·12·13·14·16·18·20·24·28·32·36px(열한 단). 굵기 400·500·600·700·800(다섯 단).
- 역할별 굵기: 큰 숫자 800 / 제목·강조(b·strong)·핵심 값·켜진 조작 700 / 단추·링크·표 머리글 600 / 작은 숫자·칸 이름·배지 500 / 메뉴 항목과 설명·라벨·날짜 같은 보조 글자 400.
- 일반 안드로이드(글꼴 한 굵기 + 합성 굵게)와 윈도우(맑은 고딕 보통·굵게)는 400·500 을 보통으로, 600 이상을 굵게로 그린다.
  그래서 보조 글자를 400·500 으로 내리는 것이 어느 기기에서나 위계를 만든다(iOS·삼성 글꼴은 다섯 단이 다르게 보인다).
- 크기를 옮기는 방향: 11px 아래는 11px 로, 같은 거리면 14px 아래는 위로(읽기), 그 위는 아래로(넘침 없음), 제목은 위로, 본문 문단 15px 는 16px.

## 방법

1. 화면마다 보이는 글자 요소의 (크기, 굵기)를 재고 태그·내용·맥락으로 역할을 정한다(`audit/type-plan.mjs`).
2. 그 값을 만든 CSS 선언을 브라우저(CDP `CSS.getMatchedStylesForNode`)에서 찾는다 — 시트·선택자·선언 블록. 물려받은 값이면 그 값을 정한 조상의 선언.
3. 한 선언을 쓰는 글자를 모두 보고 목표를 하나로 정한다: 굵기는 가장 큰 목표(제목과 보조 글자가 한 규칙을 쓰면 제목을 따른다), 크기는 요소가 많은 쪽.
4. 원본 모듈에서 같은 선택자 + 같은 선언 블록을 찾아 값을 바꾼다(`audit/type-apply.mjs`). 화면 44곳(잰 36곳 + 안내·백업 화면 8곳)의 선언 995개를 보고 290묶음을 바꿨다.
   - 손으로 정한 값(아래 H-2 와 독립 검토 반영)은 도구가 다시 바꾸지 않게 지키는 목록에 뒀다.
   - 바탕 셸 상수(`ACCOUNTBOOK_SHELL_V22811_CSS` — 옛 주소 `/assets/accountbook-shell-v22811.css` 로도 내려간다)의 세 규칙은 상수를 두고 이 판의 셸 조립에서만 바꿔 쓴다.
   - 소비 분석 리포트 보기의 인라인 CSS(`src/modules/my/analysis-page.js`)는 그대로 뒀다(R3). 한눈에 보기(`insight-page.js`)는 글자 값만 눈금으로 옮겼고 구성과 문서 높이는 그대로다(4,059 → 4,064px).
5. 측정에 잡히지 않은 규칙(오류·빈 상태·다른 화면)에 남은 눈금 밖 값 168선언은 역할을 알 수 없어 가까운 눈금으로만 옮겼다(스타일시트 셋의 원본).
6. 다시 재서 넘침·잘림·터치 영역·대비가 나빠진 화면이 없는지 본다(`audit/ux-criteria-audit.mjs` + `compare-v125.mjs`).

첫 시도에서는 바꿀 글자만 보고 선언을 고쳤다가, 제목과 보조 글자가 같이 쓰는 규칙에서 제목까지 가늘어졌다(홈의 ‘무지출 데이’·‘최근 내역’ h2 가 400).
되돌리고 3번처럼 그 선언을 쓰는 글자 전체를 보게 고쳤다.

## 고친 것

### H-1 글자 굵기·크기를 눈금으로 (V124:U-8)
- 스타일시트 셋(셸·홈·공통)의 font-weight 는 400·500·600·700·800 만, font-size(px)는 열한 값만 쓴다(그림 문자 장식 38·58px 셋만 예외). 반 픽셀 크기 없음.
- 글자 토큰(V22.9.84): 큰 숫자 34 → 36px(홈의 큰 숫자와 같게), 중간 숫자 22 → 20px. KPI 숫자의 유동 크기 19~25 → 18~24px, 화면 제목 24~34 → 24~32px.
- 규칙이 없던 단추·small 은 13px(특이도 0 인 `:where()` 규칙 — 글자 크기를 정한 규칙이 있으면 그쪽이 이긴다).
- 페이지 인라인 CSS(공개 화면·결제수단·정산·설정·가계부 전환 등 26개 모듈)도 측정에 잡힌 선언은 같은 눈금으로.

### H-2 홈의 위계 (손으로 정한 것)
- 예산 카드 라벨(‘이번 달 쓸 수 있는 돈’)·요일 글자·일별 칸의 날짜는 400. 사용률 숫자·주간 띠의 날짜·값이 있는 칸의 금액·페이스 상자의 첫 문장은 700.
- ‘예산 사용률 20%’ 칩은 한 줄(이름 400 + 숫자 700).
- 휴대폰 홈의 600 이상 글자 177개(85%) → 77개(37%), 750 이상 91개 → 1개(큰 숫자).

### H-3 밀도 (휴대폰, V124:U-13)
- 머리와 첫 카드 사이 빈 띠 38px → 12px(본문 위 여백 14 → 0 — 머리의 아래 여백 12px 와 첫 카드의 위 여백 12px 가 겹쳐 카드 사이 간격과 같아진다).
  머리(header.appTop)를 쓰는 홈·캘린더·내역 탭에 같이 걸린다. 844px 화면의 첫 화면에 ‘무지출 데이’ 카드 머리까지 보인다.

### H-4 모서리의 홀수 값 (V124:U-9 의 일부)
- 스타일시트 셋의 원본에서 9·11·13·15·17·19·21px 69선언을 8·12·16·20 으로. 잰 화면의 홀수 모서리 286 → 52개(390 폭), 810 → 48개(1440 폭). 남은 것은 페이지 인라인 CSS 와 바탕 셸의 값이다.

### H-5 남아 있던 표 (V124:U-10 의 일부)
- 설정(전체 요약)의 ‘저장된 분류별 지출 예산’ 표: 767px 이하에서 줄마다 카드로(`.scroll.abStackWrap` + `table.abStackTable` + `data-label`). 390px 에서 13px 을 옆으로 밀던 표.
- 쌓는 표(정산·오늘 예산·결제수단): 768~1099px 에서 최소 폭(760px)을 풀어 화면 안에. 오늘 예산 표는 768px 에서 83px, 사이드바가 나와 본문이 좁아지는 900px 에서 223px(1024px 에서 95px)를 옆으로 밀어야 했다.
- 옆으로 밀어야 하는 표: 390 폭 1 → 0, 768 폭 3 → 0.

### H-6 꼬리말 링크 (V124:U-12 의 일부)
- 사업자 정보 꼬리말: 글자 11px(700px 이하 10.5px) → 12px, 이메일 링크의 누르는 높이 15 → 45px(글줄 높이는 그대로 — 위아래 14px 여백을 바깥 여백으로 상쇄).
- 24px 미만 조작 영역: 390 폭 10 → 1, 768 폭 9 → 0.

## 남긴 것

### H-7 한 규칙을 여러 역할이 같이 써서 못 내린 글자 (P3, 남음)
- 켜진 것과 꺼진 것이 한 규칙을 쓰는 탭·칩(홈의 ‘일별/주별’, ‘최근 10건/30건’), 공통 `label`·`th`·단추 규칙, 표의 이름 칸처럼 굵기 선언 하나를 여러 역할이 나눠 쓰는 곳은 가장 큰 목표를 따랐다.
  그 때문에 목표보다 굵게 남은 글자가 있다(계획 도구의 blocked 목록 323줄). 규칙을 역할별로 나눠야 한다.
- 잰 화면 전체의 600 이상 비율은 66 → 47%(390 폭). 홈처럼 손으로 나누면 더 내려간다.

### H-8 간격 눈금과 색 토큰 (P3, 남음)
- 간격 값은 그대로다(화면마다 16~23가지, 홀수 값 5·7·9·11·13px 이 많다). 토큰은 있다(`--ab12-sp-*` 8·16·24·32).
- 글자색 13~14가지·바탕색 19~25가지도 그대로다. 그라디언트는 홈 2곳·분석 1곳.

### H-9 측정에 넣지 않은 곳의 페이지 인라인 CSS (P3, 남음)
- 소비 분석 리포트 보기의 인라인 CSS(R3 보호)와 차트의 SVG 글자(10px), 달력 칸의 금액·건수(10px — 넘침 방지), 회원 번호 표시(26px), 가져오기·백업 적용 결과 화면, 관리자 화면은 그대로다.
- 빠른 입력 시트의 금액·내용 칸 이름(V124:U-11)도 그대로다.

### H-10 기기별 글꼴 굵기 (P3, 확인 불가)
- 500·600 이 실제 기기 글꼴(iOS 의 Apple SD Gothic Neo, 삼성 One UI, 일반 안드로이드의 Noto Sans CJK)에서 어떻게 보이는지는 헤드리스 Chrome(윈도우)으로 볼 수 없다. 사람 확인(RELEASE-CHECKLIST V22.9.125).

## 독립 검토 (2026-11-16)

Claude 하위 에이전트가 운영 번들과 나란히 대조했다(화면·폭·상태 1,126가지 — 폭 320~1440, 빠른 입력 시트·서랍·열린 details·빈 달·알림 띠 — 의 글자 굵기·크기·넘침·겹침,
긴 금액 240가지, 자산 주소 67개의 바이트와 머리글, 300화면의 HTML 차이, 공개 127화면의 글). 판정은 P1·P2 없음, P3 아홉 건이고 아래처럼 반영했다.

1. 휴대폰의 빈 띠는 24px 가 아니라 12px 였다(본문 위 여백이 0 이면 머리의 아래 여백과 첫 카드의 위 여백이 겹친다). 내역 탭에는 규칙이 걸리지 않아 홈 ↔ 내역을 오갈 때 첫 내용이 26px 움직였다
   → 12px 를 그대로 두고(카드 사이 간격과 같다) 머리를 쓰는 화면 셋에 같이 걸리게 했다. 문서의 숫자를 12px 로 고쳤다.
2. 예산 카드 안쪽 여백 20px 규칙은 먹히지 않았다(바탕 셸의 `padding:22px!important` 가 이긴다) → 규칙을 뺐다.
3. 달력 칸의 금액을 10 → 11px 로 올린 탓에 320px 폭에서 천만 원대 금액이 다섯 칸 모두 잘렸다(운영은 두 칸, 부호까지 잘림) → 달력 칸의 금액·건수는 10px 로 되돌렸다(눈금의 예외).
4. /articles 목록이 모든 폭에서 길어졌다(390 폭 +890px) → 카드 제목 16px·설명 14px 로(운영 17·15px 보다 작게) 해 390 폭에서 6% 짧아졌다.
5. 쌓는 표의 넘침은 사이드바가 나오는 900px 에서 더 컸다(오늘 예산 223px — 운영도 같다) → 최소 폭을 푸는 범위를 768~1099px 로 넓혔다.
6. 검사의 빈틈: 새 주소가 없는 번들에서도 T-1 여덟 줄이 빈 글로 통과했다 → 먼저 200 과 본문 크기를 본다. 유동 크기의 끝값(17px 하나가 남아 있었다 → 16px), 설정 표의 줄 수, 먹히지 않는 규칙 글을 더 본다.
7. 목록 밖 화면에 900·1000 굵기가 남아 있었다(/kakao-commands·/kakao-group-flow·/my/backup-login·/backup-safety·/onboarding) → 그 화면들을 더해 다시 재고 같은 도구로 고쳤다(관리자 안내 화면은 그대로).
8. 320px 폭에서 줄이 하나 더 접히는 곳 셋(첫 화면 h2 둘, 빠른 입력 설명, 구성원 권한 설명 390px) — 잘림은 없어 그대로 뒀다.
9. 소비 분석 ‘한눈에 보기’ 는 글자 값이 바뀌었다(구성과 높이는 그대로) → 문서의 ‘그대로 뒀다’ 를 리포트 보기에만 해당하는 말로 고쳤다. 비율 글자(small)는 11px 로 따로 정했다.

강조가 과하게 빠진 곳도 되돌렸다: 글의 표 제목(caption)·구성원 머리글자·정산 상태 칸(받을/보낼 금액)은 700, 빠른 입력의 ‘자세히’ 는 600, 명령어 예시(code)는 700.
검토에서 못 본 것: 실제 기기 글꼴(그 컴퓨터에서는 600 과 700 이 같은 굵기로, 500 은 중간 굵기로 그려졌다), 픽스처가 만들지 못하는 상태(카카오 로그인 화면·가져오기 결과·오류 화면).
