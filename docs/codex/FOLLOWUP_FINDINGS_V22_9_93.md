# V22.9.93 출시 전 입력 시험과 전체 기능 검수에서 찾은 항목

2026-10-31 사용자: “출시일은 13일로 확정됬어 빠르게 검토하거 버그 수정하고 개선안 도출하고 당장 배포하고 추가적으로 검토할께 많아”. 이어서 “마지막에 mcp 연동해서 aside에서 전체 기능에 대한 테스트랑 화면 깨짐여부 등 검수해서 문제없는지 전체검사 진행하고 피드백 받아서 수정까지 진행해줘”.
실제로 쓸 말투 186줄을 해석기에 넣어 보고, 흔한 지출 낱말 303개의 분류를 봤다(운영 V22.9.92, main 1aa804b 기준). 이 문서는 발견 기록만 둔다. 상태·고친 판·검사는 `docs/codex/FINDINGS_LEDGER.md` 의 `V93:` 행에서 추적한다.
증거는 저장소 밖 `review-artifacts/v93-launch-fixes-2026-10-31/` 이다.

## 항목
- **Q-1** (P2, 입력 해석) 조사를 붙이거나 붙여 쓴 날짜 말이 날짜로 읽히지 않아 **저장은 되는데 오늘 날짜로 들어간다**.
  - 예: ‘어제는 커피 4500’·‘그저께에 택시 8000’·‘어제커피 4500’·‘어제저녁치킨 23000’·‘내일모레 회비 30000’·‘25일에 월세 500000’·‘3일에 커피 4000’. 오류 안내가 없어 사용자가 알아채기 어렵다.
  - ‘10월 3일에 커피 4000’ 은 아예 0건이었다.
  - 고침: 거래 문장 입구 `foldInputWidth` 가 날짜 말 뒤 조사를 떼고 붙여 쓴 말을 띄운다. 입구가 하나라 웹 빠른 입력·카카오·서버 해석이 같이 고쳐진다(`client/shared-input-nlu.js`).
  - ‘어제의’·‘오늘날’·‘어제자’·‘오늘회’ 처럼 뒤에 이어지는 낱말은 그대로 둔다.
- **Q-2** (P2, 입력 해석) 세 자리씩 점을 찍은 금액을 소수로 읽었다. ‘회비 12.000원’ 이 12원으로 저장되고, ‘월세 1.200.000원’·‘커피 4.500원’ 은 0건이었다.
  - 고침: ‘원’ 이 붙었거나 끝이 .000 이면 자릿수로 읽는다(달러·리터·kg·% 같은 단위가 뒤따르면 읽지 않는다). 끝이 00 이면 그 줄에 다른 금액이 없을 때만 읽는다. 그 밖(‘커피 3.750’, 점 셋 이상)은 읽지 않고 옛 판처럼 다시 묻는다.
  - ‘1.5만원’·‘7.3 커피’·‘2026.07.03’ 은 그대로다. 문장부호가 붙어도 같다(‘점심 12.000!’). 메모로 접을 때는 잇지 않는다.
  - 일부러 둔 것: ‘포인트 1.000 사용 커피 3000’ 은 두 건이다. 점 없는 ‘포인트 1000 사용 커피 3000’ 과 같고, 끝 .000 을 안 이으면 ‘커피 12.000 점심 9000’ 이 조용히 12원이 된다.
  - 예산 명령(‘식비 예산 300.000원’ 이 300원)과 웹 저장 판정(Q-11)도 같은 입구를 지난다.
- **Q-3** (P3, 분류) 흔한 지출 낱말 303개 중 120개(40%)가 기타지출로 빠졌다(삼겹살·돈까스·롯데리아·CGV·계란·우유·노트북·톨게이트 등).
  - 고침: 분류 낱말을 더해 기타는 6개로 줄었다(회·다이어트·약·스팀·카드값·세뱃돈). ‘시험관’·‘알리바바’·‘꽃게’ 같은 오탐은 except·exact 로 막았다.
  - ‘식비’는 `normalizeCategoryName` 이 따로 다뤄 일부러 넣지 않았다.
- **Q-4** (P2, 화면) 제출 잠금이 눌린 버튼의 값을 지웠다. **홈 구성의 위아래 버튼이 ‘저장했습니다’ 만 내고 순서를 바꾸지 않았고**, 관리자 화면 일괄 삭제는 ‘변경할 값이 없습니다’ 로 끝나는 구조였다(운영에도 있다).
  - 원인: `guidedUiUxClientMain` 의 잠금이 마이크로태스크에서 `button.disabled = true` 를 한다. 실제 클릭에서는 이 때가 브라우저가 보낼 값을 모으기 전이라, 막힌 버튼의 name·value 가 빠진다. 스크립트 `button.click()` 은 값을 모은 뒤에 돌아 값이 남는다(헤드리스 Chrome 의 신뢰된 클릭으로 재현).
  - 고침: 눌린 버튼(event.submitter)의 이름·값을 숨은 칸으로 남기고 막는다. 뒤로 가기로 돌아오면 지운다. 폼 밖 버튼(`form=`)을 눌렀을 때 폼 안 다른 버튼의 값을 대신 보내지 않는다.
- **Q-5** (P3, 화면) 없는 주소를 브라우저로 열면 원시 JSON 이 보였다. 고침: GET + accept text/html 은 한글 404 화면(noindex, 내 가계부·처음 화면 링크), API·스크립트 요청은 그대로 JSON 이다.
- **Q-6** (P3, 화면) 연간 리포트를 거치면 사이드바 링크의 달이 그 해 1월로 바뀌어, 다음 화면이 빈 달을 보였다. 고침: 메뉴 링크가 보던 달을 들고 간다(`/annual?month=`). 스마트 도구에 기준 달을 적었다.
- **Q-7** (P2, 입력) 목표 추가 화면이 금액에서 숫자만 남겨 ‘-100’ 이 100, ‘10만’ 이 10 으로 저장됐다. 고침: 적은 그대로 보내고 서버가 판정한다(서버 검증은 이미 있었다). 쉼표·‘원’ 은 그대로 받는다.
- **Q-8** (P3, 입력) 같은 이름 목표가 안내 없이 둘이 됐다(추가 버튼을 두 번 눌러도 생긴다). 고침: 진행 중인 같은 이름은 안내하고 막는다. 다 모은 목표는 같은 이름으로 다시 시작할 수 있다.
- **Q-9** (P3, 문구) 지출자 칸·하루 상세·스마트 도구·약관·가계부 안내에 영어 역할 이름(owner·member 등)이 보였다. 고침: 소유자·관리자·구성원·조회전용. 관리자 점검표의 내부 표기는 그대로 둔다.
- **Q-10** (P3, 접근성·입력) 고칠 수 없는 행의 읽기 이름이 ‘수정·삭제 상세 보기’ 였고, 160자가 넘는 내용이 말없이 잘렸다. 고침: 그런 행은 ‘상세 보기’, 저장 전 요약에 ‘내용은 160자까지 저장됩니다’.
- **Q-11** (P2, 입력) 웹 저장 판정이 접지 않은 원문을 읽어, 미리 보기는 읽는 ‘월세 1.200.000원’ 이 ‘금액 없음’, ‘회비 5.000’ 이 ‘단위 없음’ 으로 막혔다. 고침: 판정도 `foldInputWidth` 를 지난 글자를 읽는다. 저장하는 원문은 그대로다.
- **Q-12** (P3, 화면) 연간 화면 안의 해 화살표·해 고르기·‘가계부로 이동’ 이 보던 달을 버려 Q-6 이 그 다음 화면에서 되살아났다. 고침: 모두 같은 달을 들고 간다.
- **Q-13** (P3, 입력) 목표 금액의 ‘₩100,000’·‘1.000.000’ 이 막히고 안내가 무엇을 쓰라는지 말하지 않았다. 추가 버튼을 빨리 두 번 누르면 두 번째가 같은 이름 안내로 끝났다. 고침: 원 기호·점 자릿수를 읽고, 안내에 범위와 ‘100만’ 불가를 적고, 보내는 동안 다시 보내지 않는다.
- **Q-14** (P3, 관측) 비밀번호 변경 재인증 콜백이 가계부가 없는데도 역할을 읽어, uuid 칸에 글자 ‘credential-change’ 를 넣은 요청이 실패로 남았다(사용자 동작은 정상, 허위 경보). 고침: 이 경로는 읽지 않는다.
- **Q-15** (P3, 입력) 정기 추가 폼이 금액·지출자를 비운 채 제출됐고, 돌아갈 주소에 달이 없어 지난달 화면에서 추가하면 이번 달로 넘어갔다. 고침: 두 칸 필수, 돌아갈 주소에 달을 넣는다.
- **Q-16** (P3, 화면) 빠른 입력 버튼이 줄면 56px 원 오른쪽에 글자 첫머리 조각이 보였다(1280). 고침: 줄었을 때 간격을 16px 로 벌려 글자를 원 밖으로 민다.
- **Q-17** (P3, 화면) 360·390 에서 조회 줄의 달 칸이 105~127px 라 ‘2026년 10월’ 이 ‘2026년’ 까지만 보였다(예산·정기·결제수단·구성원·설정·전체 메뉴). 고침: 440px 이하에서 가계부 칸을 윗줄로 올린다.
- **Q-18** (P2, 화면) 다크에서 쪽마다 둔 밝은 배지 바탕은 남고 글자만 셸이 밝게 바꿔 ‘부족’·‘초과 238%’ 가 안 읽혔다(대비 1.2 안팎). /my/backup 의 카드사 글자도 셸 규칙에 져서 대비 1.2~3.8 이었다. 고침: 배지 바탕까지 다크 값으로 맞추고 카드사 글자를 흰색으로 고정했다.
- **Q-19** (P3, 화면) 리포트 날짜별 지출 축의 두 자리 날짜가 360·390 에서 글자마다 세로로 갈라졌다. 고침: 줄바꿈을 막고 막대 폭 밖으로 조금 넘치게 둔다.
- **Q-20** (P3, 화면) 권한 안내·‘가계부를 찾을 수 없어요’ 화면에 테마 스크립트가 없어 다크를 고른 사람에게도 흰 화면이었다. 고침: 스크립트를 싣고 다크 값을 둔다. 후처리가 붙이는 `ab-uiux` 의 밝은 값이 !important 라 같은 강도로 쓴다.
- **Q-21** (P2, 입력) 값 하나만 읽는 칸이 점 자릿수를 소수로 읽었다. 카카오 ‘01번 금액 12.000원’ 이 묻지 않고 12원으로 바뀌었고, 예산 대화·정기 폼의 금액도 같은 길이다. 고침: `parseAmountValue`·`normalizeKakaoEditAmountValue` 도 거래 문장과 같은 입구(`foldInputWidth`)를 지난다.
- **Q-22** (P3, 입력) ‘방금 12000원으로 바꿔줘’·‘방금 거 …’·‘방금꺼 … 수정’ 이 새 기록으로 저장됐다. 고침: 방금 기록의 금액 고치기로 읽는다. 뒤에 다른 말이 이어지면(‘방금 5000원으로 밥 먹음’) 기록이다.
- **Q-23** (P2, 입력) 고치기 값의 조사가 그대로 저장됐다. ‘01번 결제수단 현금으로’ 가 결제수단 ‘현금으로’, ‘01번 분류 외식으로’ 가 없는 분류 ‘외식으로’, ‘내용을 점심으로 바꿔줘’ 가 내용 ‘점심으로’ 가 됐다. ‘날짜 어제로’ 는 못 알아들었고, ‘01번 현금으로’ 는 내용을 바꿀지 물었다. ‘얼마로 바꿀까요?’ 에 답한 ‘5000원으로’ 는 수정을 끝내고 새 기록이 됐다.
  - 고침: 칸이 정해진 값은 조사를 뗀다. 등록된 이름은 그대로 둔다. 내용은 이름일 수 있어(‘종로’·‘을지로’) ‘으로’ 만 뗀다. 동사까지 붙은 ‘내용 커피로 바꿔줘’ 는 ‘로’ 도 뗀다.
  - 칸 이름 없이 값만 오면 조사를 뗀 값이 결제수단·날짜·구성원·분류·금액일 때 그 칸을 고친다. ‘일로’ 는 금액이 아니다.
- **Q-24** (P2, 입력) 고치거나 지우려는 말이 메모에 ‘바꿔줘’·‘삭제’ 가 남은 새 기록으로 저장됐다(‘커피 5000원으로 바꿔줘’·‘5000원으로 수정’·‘01번을 12000원으로 수정’·‘01번 만이천원으로 바꿔줘’·‘커피 4500원 삭제’·‘수정 커피 5000원’·‘금액 틀렸어 5000원이야’). ‘01번 12000원으로 바꿔주세요’ 처럼 ‘주세요’ 는 값으로 읽혔다.
  - 고침: ‘을·를’·‘주세요’·‘5천원’·‘만이천원’ 꼴을 고치기로 읽는다. 번호가 없어 어느 기록인지 모르는 말은 저장하지 않고 번호를 보라고 안내한다(저장 바로 앞에서만 본다).
  - 금액 뒤에 고치는 말이 오지 않으면 기록이다(‘바지 수정 5000원’·‘5000원으로 점심 먹음’).
- **Q-25** (P3, 입력) ‘방금 거 지워줘’·‘방금꺼 삭제’·‘마지막 거 삭제해줘’·‘아까 거 삭제’ 가 ‘이해하지 못했어요’ 였고, ‘최근 기록 삭제’ 는 목록만 보였다. ‘1번 취소’ 는 ‘01번 수정을 취소했어요’ 라고 답해 지워진 줄 알게 했다. 고침: 방금 기록 삭제로 읽는다(‘복구’ 로 되돌린다). ‘취소’ 말은 지우지 않고 안내하고, ‘1번 취소’ 는 기록이 그대로라고 말한다. ‘아까’ 는 뒤에 ‘거’·‘기록’ 이 있을 때만 기록을 가리킨다(‘아까 내용 뭐였지’ 가 내용을 바꾸면 안 된다).
  - 복구 말(‘복구해줘’·‘방금 거 복구’·‘되돌려줘’)과 번호 말의 ‘번’ 을 뺀 꼴(‘삭제 01’·‘수정 01 금액 5000’)도 같은 판에서 읽는다.
- **Q-26** (P2, 입력) 웹 한 줄 입력은 폼 하나가 한 건만 저장하는데, 금액이 둘인 문장을 앞 금액 한 건으로 저장하고 뒤 금액을 메모에 남겼다(‘커피 12000 점심 9000’, 카카오는 두 건). 쉼표 문장은 뒤 금액 한 건이 됐다(‘빵 2600, 우산 4700’).
  - 고침: 금액이 둘 이상이면 저장을 막고 나눠 적게 안내한다. Enter 로도 문장을 비우지 않고, 문장을 지우면 앞 금액만 읽어 채운 칸도 비운다. 패널을 닫았다 열어 임시저장에서 되살린 문장도 다시 센다.
  - 금액이나 내용을 손으로 고치면 본 것으로 여겨 막지 않는다. 한 줄로 여러 건을 저장하는 기능은 만들지 않았다(개선안).
- **Q-27** (P3, 화면) `/settlement-summary` 조회 줄이 360 폭에서 2×2 라 가계부 칸이 139.5px 로 잘렸다. 달 칸과 고르는 칸이 함께 있는 조회 줄은 전 화면에서 이 쪽뿐이다. 고침: 좁은 폭에서 가계부 칸과 단추가 한 줄을 쓴다.
