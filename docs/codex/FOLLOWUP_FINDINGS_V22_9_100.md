# V22.9.100 K-1 방 기록 호출 수 개선 (2026-11-04)

작업 지시서의 K-1 절과 `review-artifacts/incident-2026-11-04-kakao-latency/K1-DESIGN.md`를 기준으로 구현했다. 원문과 상세 실행 로그는 저장소 밖에 보관한다. 운영 판은 V99이며 V100은 구현 PR 검증 단계다.

- **K-1** (P1) 이미 연결된 방의 기존 구성원 기록도 첫 기록 생애주기 경로를 타면서 답 전에 DB를 26회 호출했다. 두 설정 묶음·구성원 합성 조회·일일 기록 재사용과 기존 구성원 빠른 길을 추가하고, 확정 표식 삭제·잠금 해제를 응답 뒤로 옮겼다. 일반 모드 B는 9/11회, 분류 표 부재 모드 B는 8/10회이며 고정 상한은 답 전 10·전체 12회다. 새 방 A는 29/36회, 참여 D는 일반 24/30·부재 23/29회다. `validation/validate-skill-db-calls-v229100.mjs`가 A~K, 파동, 잠금 순서, 표식, 소유권, 500건 경계, 재연결과 실패 정리를 검사한다. 생애주기 잠금 경쟁 창과 최초 appUserId 별칭 처리의 후속 B-0은 KNOWN-ISSUES에 기록한다.

## 측정 해석

- 수치는 `app.fetch` 응답 시점과 모든 `waitUntil` 완료 시점을 나누어 센다. NLU 지표는 전체 호출 수에 포함한다. B의 픽스처 파동은 5이며 실제 독립 조회 묶음은 네 단계다.
- 합성 or+embedding 거절은 기존 두 조회로 복귀한다. 첫 거절을 포함하면 일반 모드 답 전 11회, 지원 부재를 기억한 다음 요청은 10회다. 모든 embedding이 없는 별도 장면은 14/16회다.
- 사용자가 F-1 기존 별칭은 답 전 14·전체 17, F-2 최초 별칭은 강한 입력 17/19·일반 입력 22/24로 확정했다. 실측은 F-1 강한 10/12·일반 11/13, F-2 강한 17/19·일반 18/20회다. F-2 두 입력은 독립된 최초 별칭 상태에서 검사한다. B-0 에서 ≤ 10 으로 내린다. 최초 별칭 등록은 이 판에서 동기 처리로 유지한다.
- 원래 ‘빵 2500’의 최초 별칭은 처음 구현에서 22/24회였고 같은 스냅숏 재사용 뒤 18/20회다. 강한 입력보다 과거 5회, 현재 1회 더 호출하는 정확한 설정 키·조회 용도는 `K1_VERIFICATION_V22_9_100.md`의 대조표에 적었다. appUserId 없는 같은 원문 B도 10/12회로 상한을 지킨다. 운영 콘솔 연결이 해제되어 appUserId가 오지 않는다는 사용자 설명에 따라 F는 현재 운영을 막는 경로가 아니다.
- 검토에서 확인한 S2 파생 Promise 거절 누락, 호출 예산이 적을 때 메시지 잠금 해제 누락, 생애주기 DB 잠금보다 먼저 풀리는 local mutex를 고쳤다. 큐는 원래 순서를 보존하고 남은 필수 해제 비용을 예약한다. 해제가 실패하거나 생략되어도 local gate는 열린다.
