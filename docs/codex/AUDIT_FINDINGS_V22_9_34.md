## 1. V22.9.34 에서 고친 것

### 보안·데이터 손실

- **SIM-10(P1 보안):** 분류·결제수단·메모를 `__proto__`로 저장하면, 같은 인스턴스가 처리하는 다른 가계부 기록의 분류가 바뀌고 수정 금액이 0원이 됐습니다. 세 겹으로 막았습니다.
  - 빈 객체로 만든 집계 맵 79곳을 원형 없는 객체로 바꾸고, 정적 검사로 다시 생기지 않게 막습니다.
  - 기록 정리 함수는 자기 속성만 읽고, `__proto__`·`constructor`·`prototype`을 분류·결제수단 이름으로 받지 않습니다.
  - 요청 앞뒤에서 원형 오염을 지우고 운영 이벤트(`prototype_pollution_scrubbed`)로 남깁니다.
  - 이름이 원형 키와 같은 분류도 소계가 0원·NaN 이 되지 않습니다(C01, SIM-11~13).
- **SIM-1(P1 관리자):** 관리자 수정 모달이 목록 필터의 `type` 칸을 수정 폼에 붙였습니다. 그래서 메모만 고쳐도 수입이 지출로 바뀌었습니다(V22.7.2 부터). 이제 필터 칸 대신 원래 값을 싣고, 서로 다른 `type`이 함께 오면 저장하지 않습니다.
- **카카오 수정·삭제·복구(N1·D4·D3·T2·S1·N3·N4·T4·T12·T6):**
  - 풀리지 않는 날짜 접두와 "00번"은 거절합니다. 날짜가 붙은 옛 수정 명령은 새 지출로 저장하지 않습니다.
  - 저장 안내와 삭제 답장에 날짜와 기록 이름을 넣습니다. 결과를 모르는 삭제·수정은 "먼저 확인"으로 안내합니다.
  - 되돌리기 버퍼는 엄격하게 읽고 잠급니다. 읽기에 실패하면 지우지 않습니다.
  - 수정 금액은 20억이 상한입니다. 풀리지 않는 날짜는 다시 묻습니다.
  - 복구는 원래 id 로 한 번만 넣고, 다른 가계부 복구는 거절하며 `source`를 보존합니다.
  - 만료된 세션은 없는 것으로 보고, 세션 중 분명한 새 지출은 기록합니다.
  - 함께 고친 카카오 NEW 항목:
    - NEW-1(P1): 결과를 모르는 수정을 다시 보내면 다른 기록까지 바뀌던 것
    - NEW-2: "방금 금액 7000"
    - NEW-3: 세션 중 "돈까스"를 금액으로 읽던 것
    - NEW-5: 조사
    - NEW-6: 빈 날짜 머리말
    - NEW-7: 수입 삭제 문구
- **설정 화면(S2~S11):**
  - 예산 일괄 저장은 계획 지문으로 대조하고, 못 읽으면 폼을 그리지 않습니다.
  - 키워드는 바꾼 카드만 원래 값과 대조해 저장합니다.
  - 자산·순자산 기록, 계정 통합의 단톡방 연결, 관리자 옛 비밀번호, 카카오 예산 복사, 설정 분류는 모두 엄격하게 읽고 잠급니다.
  - 목표·챌린지·정산은 가계부 삭제와 같은 잠금을 씁니다.
  - 관리자 백업은 못 읽은 자료가 있으면 파일을 만들지 않습니다.
  - 홈 배치는 못 읽으면 기본값 폼을 그리지 않습니다.
- **T3:** 추천 반복 거래와 새 정기 규칙은 이번 달에 이미 같은 지출이 있으면 이번 달에 반영한 것으로 둡니다.
- **2차 B12(=T5):** 서로 다른 CSV 미리보기를 동시에 저장해도, 가계부 가져오기 잠금 안에서 중복 확인과 저장을 하므로 한 번만 들어갑니다.
- **2차 B13(=T14):** 결과를 모르는 저장의 재시도
  - 웹 빠른 입력은 요청 id 를 기록의 기본 키로 써서, 90초가 지나 다시 보내도 한 번만 저장합니다.
  - 저장은 됐는데 응답만 잃었으면 id 로 확인해 "저장됨"으로 알립니다.
  - 카카오 새 기록도 확인하지 못한 id 를 남겨 두고, 다시 보내면 같은 id 로 넣습니다.
- **2차 B14:** 오래 열어 둔 수정 폼은 바꾼 칸만 저장합니다.
  - 그 사이 다른 곳에서 바뀐 칸을 또 바꾸면 저장하지 않고 지금 값을 보여 줍니다.
  - 적용 범위는 홈 기록 카드, 관리자 모달, 달력 날짜 시트입니다.
  - 금액만 고쳐도 원문이 메모로 들어가던 것도 고쳤습니다.
- **2차 B15:** 가져오기 결과를 "저장 안 됨·저장 완료·확인 필요" 셋으로 나눕니다. 결과를 모르는 행에는 다시 가져오라고 하지 않습니다.
- **2차 B11:** 정산 완료가 비율·인원수·품목별 조건을 함께 보내고 다시 계산합니다.
  - 이력에 조건과 사람별 부담액을 남깁니다.
  - 화면을 연 뒤 지출이 바뀌었으면 저장하지 않습니다.

### 금액·날짜 해석

- **D1·N2:** 날짜(10/3·10.3·7-15)·시각(19:40)·카드 끝자리·가린 카드번호·카드 문자의 누적·잔액 금액을 금액으로 읽지 않습니다. 예전에는 "10/3 52000 마트"가 카카오에서 3건으로 저장됐습니다.
- **D2:** "부모님 용돈", "조카 세뱃돈", "용돈 드림", 수수료·배송비는 지출입니다. 아무 말 없는 "용돈 30000"은 V22.9.30 결정대로 수입입니다.
- **N6·D8·D4:**
  - 엊그제·그끄저께, "이틀/일주일/한 달 전", 말일, 작년·올해·내년 날짜를 웹·카카오가 같은 날로 읽습니다.
  - 연도 없는 날짜가 반년 넘게 앞이면 작년으로 봅니다.
  - 날짜 말은 메모에 남지 않습니다. "1일 전기요금"의 메모가 "기요금"이 되던 것도 고쳤습니다.
  - 수정·삭제 명령에서는 "엊그제"를 모호하다고 보고 다시 묻습니다.
- **N11:** 단위 없는 한 자리 금액("택시 7")은 저장하지 않고 단위를 묻습니다.
- **D15:** 화면을 연 뒤 자정을 넘기면 빠른 입력의 오늘도 다음 날이 됩니다.
