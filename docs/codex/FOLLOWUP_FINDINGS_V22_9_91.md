# V22.9.91 계정 잇기 요청과 만들며 찾은 항목

2026-10-30 15:30 무렵 사용자가 붙여 넣은 글 2번: “로그인 없이 바로 가계부가 나오도록 계정 잇기가 필요해”. 같은 날 조사(`review-artifacts/identity-link-2026-10-30/RESEARCH.md`)의 권장 A 를 보고하자
사용자가 “좋아 추천으로 진행하자 다음단계 진행”이라고 했다. L-2 는 L-1 을 만들며 관리자 계정 통합을 함께 쓰다 찾았다.
이 문서는 발견 기록만 둔다. 상태·고친 판·검사는 `docs/codex/FINDINGS_LEDGER.md` 의 `V91:` 행에서 추적한다. 파일 이름은 V22.9.90(main 8c54a9e) 기준이다.

## 항목
- **L-1** (P2, 카카오톡 → 웹) 단톡방 기록 계정과 웹 카카오 로그인 계정이 따로 있다. 오픈빌더 ‘웹가계부’ 버튼(v4.1 웹링크)을 누르면 카카오톡 인앱 브라우저에 로그인 화면이 나오고, 로그인해도 단톡방 가계부가 보이지 않을 수 있다.
  - 원인 1: 웹 로그인은 인앱 브라우저에서도 ‘카카오로 시작하기’를 직접 눌러야 한다(`auth/kakao-oauth.js`, `my/households-lifecycle.js` 의 로그인 화면).
  - 원인 2: 그룹 챗봇에 카카오 개발자 앱이 연결되지 않아 방 요청에 appUserId 가 없다. 방 기록 계정(botUserKey)과 웹 계정(카카오 회원번호)을 이을 단서가 없다(V77:N-7, KNOWN-ISSUES V22.9.88 절).
  - 고침(앱 쪽): 인앱 브라우저 자동 로그인(prompt=none), appUserId 가 오면 잇기 제안, 같은 카카오 계정으로 방금 로그인한 브라우저에서만 합치기(한쪽이 비면 바로, 둘 다 있으면 확인 뒤), 관리자 화면 연결 진단.
    - 합치기는 스위치 `KAKAO_ACCOUNT_LINK_ENABLED`(기본 꺼짐)를 켜야 한다(병합 전 독립 검토 4). 꺼져 있어도 제안과 진단은 남는다.
  - 남은 일(각각 사용자 승인 뒤):
    1. 콘솔에서 웹 로그인 앱 1489689 를 그룹 챗봇(운영·개발 채널)에 연결한다. 그 전에는 자동 로그인만 동작하고 잇기 제안은 생기지 않는다.
    2. 운영자 자신의 계정으로 appUserId 도착과 제안을 확인한 뒤 스위치를 켠다.
- **L-2** (P3, 관리자 계정 통합) 보조 계정이 카카오 로그인을 `users.kakao_user_key = kakao_login:<회원번호>` 로만 갖고(강한 식별 행·링크 별칭 없음) 있으면, 통합 뒤 그 카카오 계정의 웹 로그인이 새 빈 계정을 만든다.
  - 통합 함수 `accountbook_merge_users_v227` 이 보조 계정의 kakao_user_key 를 `merged:…` 로 바꾼다(`schema_v22_7_0_auth_atomicity.sql`).
    로그인 주인 찾기(`auth/identity-reauth.js` lookupKakaoLoginOwner: 강한 식별 → 링크 `kakao_login:` → users.kakao_user_key)가 더는 찾지 못한다.
  - 강한 식별이 생기기 전(V22.7)에 카카오로 가입하고 그 뒤 웹 로그인을 하지 않은 옛 계정, 또는 로그인 때 강한 식별로 옮겨 적기(findUserByKakaoLoginId)가 실패한 계정만 해당한다.
    관리자 통합 화면(`/identity-audit`)에서만 일어난다.
  - 고침: 통합 뒤 링크 다시 쓰기(전역 잠금 안)에서 두 계정 중 kakao_user_key 가 `kakao_login:` 인 쪽의 링크 `kakao_login:<회원번호>` 를 주 계정으로 둔다(`admin/identity-merge.js`).
