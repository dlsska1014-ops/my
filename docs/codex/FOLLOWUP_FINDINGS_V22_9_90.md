## 항목
- **F-1** (P3, 웹 삭제) 삭제를 누르면 5초 뒤에 지워지고, 되돌리기는 그 5초(보내기 전)에만 있다(`client/lucian-b-mains.js` accountbookTransactionDeleteClientMain, V22.9.47 Lucian #070·#071).
  - 사용자는 삭제가 늦다고 느꼈다. 5초 안에 화면을 떠나면 삭제가 취소됐다.
  - 고침: 누르면 바로 보낸다. 서버가 돌아갈 주소에 되살리기 표(60초, 서명)를 싣고, 홈 알림이 ‘되돌리기’ 폼(POST /my/restore)을 5초 보인다.
    서버는 DB 감사 기록(지운 행 전체)으로 같은 기록 번호를 다시 넣는다. 새 DB SQL 은 없다.
- **F-2** (P3, 한 줄 입력) 한글 조합 중에는 한 줄 입력을 읽지 않아 마지막 글자가 띄어쓰기 전까지 결제수단·분류에 들어가지 않는다(`my/mobile-home.js` 홈 스크립트, V22.8.89 의 조합 중 input 건너뛰기).
  - ‘점심 12000원 현금’을 치면 ‘현’까지만 읽어 결제수단이 비었다. 띄어쓰기나 다른 입력을 하면 그때 반영됐다.
  - 고침: 조합 중에도 글자마다 읽는다. 읽기는 한 줄 입력 칸을 바꾸지 않아 조합을 끊지 않는다. 조합 중 Enter 는 예전처럼 저장하지 않는다.
- **F-3** (P3, 관제 이용 현황) 카카오 기능 순위 1위가 ‘알 수 없음’(10월 129회 중 53회)이다(`kakao/skill-handler.js`·`runtime/ops-telemetry.js` nluDiagnosticFields).
  - 기능 이름을 메뉴 낱말 판별(detectKakaoNaturalIntent)로만 붙여 기록 글과 고치기 명령이 UNKNOWN 이었다.
  - 판별 이름 HOUSEHOLD_CREATE·HOUSEHOLD_JOIN 이 저장 허용 이름 CREATE_HOUSEHOLD·JOIN_HOUSEHOLD 와 달라 UNKNOWN 이 됐다.
  - 고침: 메뉴 판별이 UNKNOWN 이면 처리기가 읽은 대로 센다(기록 → TRANSACTION, 고치기 명령 → EDIT). 판별 이름 둘은 저장 이름으로 바꿔 센다.
    관제 이름표(`monitoring/model.mjs`)는 이미 있어 관제 배포·SQL 은 필요 없다.
