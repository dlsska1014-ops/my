# V22.9.40 패키지 B — 광고 게이트(ADS_MODE) 준비

- 브랜치: `claude/v22940-ads-gate` (기준 main `a93db22` = V22.9.39-PUBLIC-GUIDES)
- 상태: 코드·검사 준비 완료. **운영 변수는 설정하지 않았다(기본값 review).** AdSense 재심사(2026-10-11 접수)가 승인되기 전에는 `ADS_MODE` 를 만들지 않는다.
- 이 문서는 통합 단계의 버전 의식 문서(`VERSION.txt`, `CHANGELOG.md`, `KNOWN-ISSUES.md`, `DEPLOYMENT_MATRIX.md`, `docs/ASIDE_V22_9_40.md` 등)를 대신하는 패키지 기록이다. 그 파일들은 고치지 않았다.

## 1. 설계 요약

승인 뒤 코드 재배포 없이 Worker 변수 하나로 광고를 켠다. 변수가 없거나 정확히 `"live"` 가 아니면 HTML·헤더가 게이트 전(a93db22)과 **바이트 단위로 같다**.

| 변수 | 읽는 곳(소스 전체에서 한 곳) | 유효한 값 | 그 밖의 값 |
|---|---|---|---|
| `ADS_MODE` | `adsMode(env)` | 정확히 `"live"` | 없음·`"LIVE"`·`"Live"`·`"on"`·`"1"`·`"review"`·`""`·앞뒤 공백 → 모두 `review` |

## 4. CSP

### 공식 문서 확인 (2026-10-12)

- AdSense 고객센터 "Integrate the AdSense ad code with a Content Security Policy (CSP)" — https://support.google.com/adsense/answer/16283098
- Google Publisher Tag "Content Security Policy" — https://developers.google.com/publisher-tag/guides/content-security-policy

두 문서 모두 **도메인 허용 목록 방식은 지원하지 않는다**("we only support strict CSP (option 2)", 광고 도메인이 계속 바뀌어 목록이 낡으면 광고가 깨진다)고 적는다. 지원하는 예시는 `object-src 'none'; script-src 'nonce-{random}' 'unsafe-inline' 'unsafe-eval' 'strict-dynamic' https: http:; base-uri 'none'` 이고, 이보다 **느슨한 정책은 써도 되지만 더 엄격하면 예고 없이 깨질 수 있다**고 한다. 예시에는 `default-src`·`frame-src`·`connect-src` 가 없어 iframe·통신은 제한이 없다. 호스트 목록은 어느 문서에도 없다.

그래서 요청서의 "최소 후보" 호스트 목록(허용 목록)은 쓰지 않았다(공식 문서와 다르면 공식 문서를 따른다). nonce 방식(공식 strict)도 쓰지 않았다. 이유: 허용 화면에 nonce 없는 인라인 처리기(`toggleAbSideNav()`·`toggleAbMobileNav()` 내비 토글, `window.print()` 인쇄 버튼)가 있고, nonce 를 걸면 `'unsafe-inline'` 이 무시돼 이 처리기가 막힌다. 고치려면 심사 모드 HTML 을 바꿔야 한다(금지). 대조 실험으로 확인했다: 공식 예시 정책을 걸고 모든 `<script>` 에 nonce 를 붙여도 `/reports` 390px 의 메뉴 버튼이 동작하지 않고 `script-src-attr inline` 위반이 났다(증거 `screen-evidence.json` 의 `control`).

결론: **live·허용 화면에서만**, 광고 코드가 우리 문서 안에서 쓰는 지시어를 공식 예시의 하위 호환 해석(`'unsafe-inline' 'unsafe-eval' https:`) 수준으로 연다. 이는 공식 예시보다 느슨한 쪽이므로 지원 범위다. 기존 정책에 이미 `'unsafe-inline'` 이 있어 스크립트 주입 방어력은 지금과 같은 수준이다.

| `default-src`, `base-uri`, `object-src`, `frame-ancestors`, `form-action`, `font-src`, `worker-src` | 그대로 | 광고 코드가 필요로 하지 않음. 글꼴은 막혀도 기본 글꼴로 보인다 |

0. **승인 전에는 아무것도 하지 않는다.** 재심사 중 `ADS_MODE` 를 만들면 공개 가이드에 광고 코드가 나간다.
1. 통합 판(V22.9.40)이 배포돼 있는지 확인: `/ready` 응답에 `"ads_mode":"review"` 가 있어야 한다(없으면 게이트가 없는 이전 판).

2. **배포 검사 도구를 먼저 고친다(통합 단계 할 일 4).** `tools/verify-deployment-v22920.mjs` 의 "AdSense owner" 항목은 `/` 에 `adsbygoogle.js` 가 없어야 통과한다. 고치지 않고 live 로 바꾸면 이후 배포 스크립트의 승격 뒤 공개 검사가 실패한다.

## 8. 남긴 위험

- **배포 검사 도구 충돌**: `tools/verify-deployment-v22920.mjs` 의 "ad runtime remains disabled during review" 단언 때문에 live 상태에서 배포 스크립트의 공개 검사가 실패한다. 이 패키지에서는 공유 배포 도구를 고치지 않았다(범위·다른 패키지와의 충돌 회피) → 통합 단계 할 일 4.
- **CSP 폭**: live 허용 화면에서는 `script-src`·`connect-src`·`style-src` 가 모든 https 출처를, `frame-src` 가 모든 https iframe 을 허용하고 `'unsafe-eval'` 이 생긴다. 기존에도 `'unsafe-inline'` 이 있어 주입 방어력은 같지만 CSP 평가 도구는 경고를 낸다. 더 엄격하게 가려면 먼저 인라인 처리기(내비 토글·인쇄)를 리스너로 옮기고(심사 모드 HTML 변경 → 별도 판) 공식 strict(nonce + strict-dynamic) 로 가야 한다. 바꾸기 전 `Content-Security-Policy-Report-Only` 로 시험하라는 것이 공식 권고다.
- **도메인·지시어 변화**: 글꼴(`font-src`)·워커(`worker-src`)·미디어는 그대로 막혀 있다. Google 이 문서 안에서 이런 자원을 쓰기 시작하면 해당 기능만 깨질 수 있고, 고치려면 코드 변경이 필요하다.
- **`Referrer-Policy: no-referrer`**: 그대로 두었다(요청 범위). 광고 요청은 페이지 주소를 매개변수로 보내므로 동작할 것으로 보지만 운영에서 확인하지 않았다. 승인 뒤 광고가 채워지지 않거나 "알 수 없는 사이트"로 잡히면 허용 화면에 한해 `strict-origin-when-cross-origin` 을 검토(코드 변경).
- **로그인 화면의 제3자 스크립트**: `/reports`·`/annual`·`/smart-tools` 에는 개인 지출 요약이 있고, live 에서는 Google 광고 스크립트가 같은 문서에서 돈다(문서 내용을 읽을 수 있는 권한). 정책 문구는 "생활비 리포트 화면에 광고 표시"를 고지하고 "거래 내용을 광고주에게 판매하지 않는다"는 기존 문장을 유지한다. 허용 여부는 운영 판단으로 다시 확인할 것.
- **EEA 동의**: Privacy & messaging 미설정. 쿠키 안내의 "지역별 동의" 문장과 실제가 어긋나지 않게 6절 4를 먼저 한다.
- **정책 수정일**: live 로 바꾸면 정책 문구가 바뀌지만 표시 수정일·sitemap `lastmod`(2026-10-11)는 그대로다(코드에 고정). 기존 문구가 "향후 광고를 활성화하면 쿠키를 사용할 수 있다"고 미리 고지하고 있어 범위 안이지만, 전환일 기록 방식은 통합 단계에서 정한다.
- **자동 광고**: 슬롯 id 없이 live 로 바꾸면 로더만 남아 대시보드 자동 광고 설정에 따라 허용 화면 어디든 광고가 들어갈 수 있다(금지 화면에는 로더가 없어 불가).
- **확인하지 못한 것**: 실제 광고 게재(오프라인이라 로더 실패), 실제 모바일 기기·iOS Safari·카카오 인앱 브라우저, 운영 Cloudflare 변수 저장·배포, AdSense 대시보드 설정.
- 픽스처 화면 검사에서 보인 콘솔 경고 2종(manifest enctype, 메뉴 토글 뒤 aria-hidden 초점)은 review 대조에서도 똑같이 나와 이 변경과 무관하다.
