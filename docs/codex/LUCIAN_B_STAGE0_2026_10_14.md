## 현행 경계와 구현 준비

- 월 전체 조회는 `mobile-home.js`에서 필터·50행 페이지 처리보다 먼저 완료됩니다. `filterMobileTransactionRows`를 재사용하여 추가 COUNT·목록 호출 없이 후보를 계산할 수 있습니다. 조회 오류는 빈 배열로 바꾸지 않습니다.
- 분류는 `category_text` 우선순위와 중복 `category` 호환이 있으므로 함께 해제합니다. 새 초점 동작은 V5 자산에 넣어 기존 인라인 추출 모바일 자산을 보존합니다.
- 기존 `/admin/delete`는 명시적 JSON 요청에도 303을 반환했습니다. RPC 오류를 모두 “기존 기록은 유지됩니다”로 안내하여 불명확 결과 구분이 필요했습니다.
- 저장소 SQL의 감사 삭제 RPC는 `{deleted:true,id}`를 반환합니다. QA 픽스처는 거래 행 배열을 반환하므로 기존 SQL 계약에 맞춥니다. SQL 변경·실행은 필요하지 않습니다.
- 일별 목록은 250행 표시 제한이 있어 부재 판정에 사용하지 않습니다. 인증된 가계부와 정확한 ID의 존재 여부만 반환하는 최소 읽기 경로를 준비합니다.
- 기존 거래 상세·일별 팝업의 확인·submit 처리와 공통 submit 잠금이 겹치지 않도록 캡처 단계에서 B 삭제 제출을 처리합니다. 목표의 pagehide 자동 전송은 재사용하지 않습니다.
