# D 열 연결·재분석 계약

V55 완료본을 기반으로 제목이 있는 표의 날짜·금액·수입/지출 구분·수입금액·지출금액·내용·분류·결제수단·지출자·무시 연결을 수정합니다. 제품 소스의 작성자는 한 명이며 독립 읽기 전용 탐색/검토를 사용합니다.

## 파서와 메타데이터

열은 제목 문자열 대신 표 구간과 0부터 시작하는 열 인덱스로 식별합니다. 자동 연결과 사용자 delta를 분리하며 변경 없는 열의 field/exact/외화/원화 메타데이터를 보존합니다. 유효 연결은 셀 정렬·금액·부호·날짜/파일 연도·요약·문맥 추론에 함께 적용합니다. memo/category 다중 열 합치기와 날짜 없는 정상 표의 내용 날짜 보완을 유지합니다.

통화·원문·시간의 자동 연결은 읽기 전용입니다. 통화/원문 필드로 다른 열을 옮기는 요청도 허용하지 않습니다. 외화 헤더/명시 통화/외화 표기는 원래 안전 규칙을 유지합니다. 무시한 열은 추론에서 제외하지만 원문에는 남깁니다. 새 단일 필드 충돌과 단일/분리 금액 방식 충돌을 설명하며 기존 자동 연결의 중복을 소급 거절하지 않습니다.

입력 5 MiB·HTTP 5000 논리 레코드·파서 최대 10000·4096열·250000 구분 셀과 저장 상한을 유지합니다. 메타데이터는 64열씩, 제목 80자·샘플 48자로 제한합니다. 페이지 밖 자동 연결도 분석하며 사용자 수정은 256개/요청 JSON 16KiB 이하입니다. 연결은 정수 인덱스·허용 필드·중복/없는 열·읽기 전용 범위를 서버에서 검사합니다.

## 요청과 원본 수명

새 UI는 mapping_protocol=1과 원본, mapping_delta를 POST합니다. 이전 결과가 있는 변경은 유효한 previous_import_token을 제출합니다. 최초 분석과 재분석을 같은 문서에서 처리하고 원본 File/textarea는 현재 탭 메모리에만 보관합니다. 파일/변환/연결/요청 리비전, AbortController와 늦은 응답 검사를 함께 사용합니다. 네트워크 실패와 취소 뒤 입력/연결을 유지하고 자동 재요청하지 않습니다. 원본이 사라지면 같은 파일/문장을 다시 선택하도록 안내합니다.

결과가 바뀐 재분석은 이전 행 선택을 이어 쓰지 않습니다. 기존 HTML POST 경로는 유지하며 같은 출처·현재 사용자/가계부/권한 검사를 거칩니다. 새 런타임은 가져오기 HTML에만 포함하고 별도 전역 자산/조회는 추가하지 않습니다.

## 상태와 저장

상태 키는 my_import_source_v22955:SHA256(가계부|원본 해시)로 유지합니다. V55 상태에 preview를 추가하고 mapping 안에 해시·별도 revision·직전/request revision·jti·사용 여부·검증한 날짜 기준/선택 연도만 둡니다. 원문/샘플/파일과 전체 delta는 영속 상태에 저장하지 않습니다. 합성 검증의 상태 직렬화는 1500바이트 미만이며 고정 길이 식별자와 날짜 기준만 보관합니다. 임대·권한·읽기·CAS 실패는 쓰기 없이 종료합니다.

매핑 preview와 commit의 상태 변경은 같은 transaction-import 가계부 임대와 기존 revision CAS로 직렬화합니다. pending/complete/failed와 읽기 중 정확히 확인된 complete에서도 mapping을 보존합니다. 기존 PostgREST LIKE 단일 operand와 고정 ID/값 확인을 유지합니다. 별도 매핑/날짜 키로 pending 보호를 분리하지 않습니다.

같은 원본/기준/연결의 재분석은 날짜 기준과 jti/고정 ID, 매핑 리비전을 유지합니다. 저장 전 연결 변경은 새 매핑 리비전으로 이전 후보의 commit을 거절합니다. 사용 전 같은 계열의 직전 후보를 이용한 진행 중 수정과 같은 요청 결과의 재발급을 허용하며 현재 후보만 저장할 수 있습니다. 토큰을 생략한 최초 분석은 미사용 후보를 교체할 수 있으나 이전 후보를 무효화합니다. 사용한 매핑의 초기화나 새 ID 발급으로 이어지지 않습니다.

저장을 시작한 계열의 연결/날짜 기준 변경은 제한합니다. 같은 연결의 120/120/60/0 후속 묶음을 유지합니다. V55 토큰/직접 POST도 현재 매핑 상태가 있으면 같은 최신성 검사를 받습니다. 사용한 고정 ID의 실제 값이 다르면 단순 성공/중복으로 안내하지 않습니다. 상태는 기존 설정의 보관 계약을 따르며 토큰은 30분 뒤 만료됩니다. 사용/pending 보호를 만료·새로고침으로 자동 삭제하지 않습니다.

## 확인 경계

금액 가리기는 단위 없는 숫자와 외화·메모 샘플을 시각/ARIA 모두에서 가립니다. 입력값과 저장값은 바꾸지 않습니다. 새 상태 안내에는 금액을 넣지 않고 같은 문장을 타이핑마다 다시 알리지 않습니다.

E-15 완전 복원·운영 CPU·실기기와 만료/소실된 불명확 저장 토큰의 복구는 후속입니다. 변경한 다른 파일 전체를 같은 작업으로 판정하지 않습니다. C 비교를 자동 시작하지 않으며 SQL/RPC/RLS·환경변수·외부 콘솔·Git 게시·업로드·배포는 수행하지 않습니다. 최종 결과와 사용자 확인 절차는 외부 FINAL_REPORT를 확인합니다.

독립 검토에서 확인한 외화 별칭 재연결, sheet 안내·윤년 기준에 따른 제목 행 불일치, 긴 인식 제목의 요약 크기를 수정했습니다. 제목 행/구간은 원본의 기본 날짜 분석 뒤 고정하고 유효 연결만 바꿉니다. 기존 매핑 요약 제목도 80자로 제한하며 검증 가능한 크기보다 큰 토큰은 발급 단계에서 거절합니다.

저장 요청을 발송한 뒤에는 행 선택과 구분도 잠그고 전송한 값을 보존합니다. 응답/본문 유실은 유효한 원래 토큰과 같은 ID로 명시적으로 다시 확인할 수 있지만, 서버의 HTTP 4xx 거절을 받은 후보는 본문이 유실되어도 다시 활성화하지 않습니다. 불명확 폼은 문서에 다시 붙인 뒤 합계와 구분을 갱신합니다.
