## T-16 저장 알림 ‘실행 취소’

V22.9.86 은 삭제 길이 ‘이 세션이 방금 만든 기록’을 보지 않아 만들지 않았다(`DESIGN_FINDINGS_V22_9_86.md` T-16 절). V22.9.87 은 주소 값(`saved_rid`)을 믿지 않고 서버가 서명한 표만 믿는다.

- **표:** 기존 용도 표 도우미(`auth/identity-reauth.js` signedPurposeToken/readPurposeToken)를 쓴다.
  - 서명은 HMAC(USER_SESSION_SECRET, "quick-undo:" + 본문)이라 다른 용도 표(비밀번호 변경 확인·카카오 로그인 상태)와 섞이지 않는다.
  - 담는 것은 기록 번호·가계부·만든 사용자·기록 지문(저장한 일곱 칸의 SHA-256 앞 32자)이고, 60초 뒤 끝난다.
  - **새 Secret 은 없다.** V86 제안은 새 Secret(승인 필요)을 적었지만, 이미 있는 비밀에 용도를 붙이는 이 저장소의 방식으로 충분했다.
  - 주소에는 금액·메모가 남지 않는다.
  - 로그인 사용자 세션이 이번 요청으로 새로 만든 기록(`msg=added`)에만 준다. 관리자 세션과 다시 보낸 같은 요청(`already_saved`)에는 없다.
- **`POST /my/undo`**(`my/transactions.js` handleMyQuickUndo):
  - 표가 이 로그인 사용자 것이고 60초 안이어야 한다.
  - 지울 기록과 가계부는 주소가 아니라 표에서 읽는다.
  - 그다음은 `/my/delete` 와 같은 검사다: 가계부 쓰기 권한, 내 기록이거나 소유자·관리자, 구성원 ‘기록만’ 정책.
  - 저장 뒤 바뀐 기록은 지우지 않는다(`undo_changed`).
  - 지우기는 같은 감사 함수를 거친다(`deleteTransactionWithAudit`, actor user).
  - 같은 출처 검사는 라우터 전역 그대로다.
  - 돌아갈 곳은 저장했던 화면(알림 값을 뺀 return_to, 바깥 주소면 그 가계부 홈)이다.
- **알림:**
  - 표가 맞으면 ‘실행 취소’ 폼 단추다(JS 없이도 된다).
  - 표가 없으면(관리자 세션 등) ‘수정·삭제 화면 열기’ 링크다.
  - 기록을 바꿀 수 없는 사람(조회 전용·‘기록만’ 구성원)에게는 둘 다 없다.
  - 단추가 있는 알림은 12초 보인다(지시서: 10초 이상). 마우스나 키보드 초점이 알림 안에 있으면 모든 알림이 멈춘다.
  - 단추 CSS 는 !important 를 쓰지 않는다. 고대비(forced-colors) 모드의 단추 테두리 규칙이 옆 링크처럼 걸린다.
- **검사가 보는 거절:**
  - 꾸민 표: 서명을 바꾸거나, 내용을 바꾸거나, 다른 비밀·다른 용도로 서명한 것
  - 서버가 다른 용도로 준 진짜 표
  - 남의 세션, 만료(61초 뒤), 저장 뒤 금액·메모 수정
  - ‘기록만’ 구성원, 가계부에서 나간 사람
  - 교차 사이트(403), 로그인 없음, 바깥 return_to, 관리자 세션, already_saved
  - 두 번 누름은 `record_not_found` 다.
  - 소유자가 다른 지출자로 저장한 기록과 구성원 자기 기록은 취소된다.
  - 서버의 지문 검사를 빼면 이 검사가 실패하는 것도 확인했다.
- **남은 질문:** 실행 취소는 성공 알림에만 있다. 예산을 넘겨 경고로 뜨는 저장 알림(‘예산 보기’ 링크)에도 둘지는 사용자가 정한다.

## T-20 `/my` 시작 화면: 로그인 먼저

공개·로그인 묶음(T-20~T-22)은 에이전트가 따로 만들고(`claude/v22987-public`) 통합 때 이 브랜치로 옮겼다. 통합 때 고친 것은 따로 적는다.

- 순서:
  1. 머리(장부 마크 타일 → `/`, 오른쪽 ‘서비스 소개’)
  2. 제목·한 줄
  3. 카카오 로그인(첫 화면의 유일한 채운 버튼)
  4. ‘로그인 이름으로 로그인’ 접힘(`<details>`, JS 없이 열린다)
  5. ‘카카오에서 기록한 가계부 이어 열기’
  6. ‘처음이신가요? 새 계정 만들기’·‘먼저 둘러보기 →’
  7. ‘카톡 한 줄 → 웹 기록’ 예시 카드
  8. 가입
  9. 기존 기능 미리보기
- 로그인 이름 칸:
  - 칸 아래 오류(`aria-invalid`·`aria-describedby`)와 비밀번호 보기 단추(JS 가 있을 때만)를 둔다.
  - 카카오 로그인이 꺼진 서버이거나 로그인 오류로 다시 그린 화면은 펼쳐 둔다.
  - 서버 검증·문구는 그대로다.
- 측정(카카오 로그인 켬):
  - 카카오 버튼 위치는 390×812 에서 y 3320 → 207, 1280×800 에서 y 1594 → 216 이다.
  - 첫 화면 채운 버튼은 카카오 하나다(라이트·다크·에메랄드).
  - 데이터 요청·바깥 요청은 0이다. 문서는 48 KiB 안이다(48,709 → 47,959 B, 통합 때 고친 두 말풍선 색 +82 B 포함).

  - ‘이어 열기’ 접힘은 사용 안내(`/how-it-works`)가 가리키고 있어 남겼다.
- **통합 때 고친 것:** 이 화면의 카톡 말풍선 두 곳이 노랑이었다. 예시 카드(`.exBubble`)는 카카오 노랑(#FEE500), 아래 기존 기능 미리보기의 내 말풍선(`.chatBubble.user`, V22.9.32 이전부터)은 #FFEB57 이었다.

## T-22 공유 미리보기 이미지(og:image)

  - image/png, 1년 캐시(immutable), nosniff

  - ETag `ab-og-v22987`
  - 통합 때 불변 자산 검사의 고정 목록에도 넣었다(PNG 도 ETag 판 규칙을 따른다).
