# V22.9.124 UI/UX 기준 점검 (2026-11-15)

사용자가 2026-11-15 오후에 “전체적인 안정화와 버그류 배치 UI UX 점검 개선하고 … UI UX 프롬프트 좋은 예시가 왔는데 기준으로 점검한번해서 개선점 있는지 봐줘” 라고 하며 점검 기준 넷을 주었다.
- 기준 1 위계·밀도: 가장 큰 위계·밀도 문제 다섯, 간격 눈금·글자 눈금·색 토큰 최대 다섯, 그라디언트 없음, 1440·390 에서 확인.
- 기준 2 폼: 한 열, 입력칸 위 라벨, 글쇠마다가 아니라 칸을 떠날 때 검증, 무엇을 하라는지 말하는 오류, 포커스·비활성·기다림·오류 상태.
- 기준 3 반응형: 390·768·1440, 터치 영역 44px 이상, 768 아래에서 표는 쌓은 카드, 가로 스크롤 없음, 데스크톱 배치는 그대로.
- 기준 4 WCAG 2.2 AA: 대비 4.5:1, 보이는 포커스 링, 글쇠 이동, 아이콘 단추의 이름, 움직임 줄이기.

운영 V22.9.123 코드(origin/main a53ffd2)의 화면 36곳(로그인 뒤 27 + 공개 9)을 헤드리스 Chrome 으로 390·768·1440 폭에서 띄워 숫자로 쟀다. 픽스처만 썼고 운영·DB 에는 닿지 않았다.
측정 도구와 전후 결과는 저장소 밖 `review-artifacts/v124-prelaunch-polish-2026-11-15/audit/` 에 있다(`ux-criteria-audit.mjs`, `before/`·`after*/` 의 report.json 과 사진).
같은 날 Aside 의 카카오톡 연동으로 실제 단톡방에서 V22.9.116~123 의 사람 확인 항목을 돌렸다(아래 ‘카카오 실제 단톡방 확인’).

## 잰 결과 (고치기 전)

- 가로 스크롤: 화면 36곳 × 폭 3개 모두 0.
- 대비 4.5:1 미달(큰 글자 3:1): 밝은 모드·다크 모드 모두 0.
- 이름 없는 조작 요소(단추·링크·입력칸): 0. 기호만으로 된 이름·자리표시만 있는 입력칸도 0.
- 포커스 표시: 조작 요소 4,036개 가운데 표시 없음 0(빠른 입력칸 1개는 화면을 열 때 이미 포커스가 있어 생긴 측정 착오), 약함 3(결제수단 화면의 표 상자 — U-3).
- 움직임 줄이기(prefers-reduced-motion: reduce)에서 남는 전환·애니메이션: 0. 본문 바로가기 링크가 첫 포커스 자리에 있다. tabindex 양수 없음.
- 44px 에 못 미치는 조작 영역(390 폭): 화면마다 0~8개, 키워드 화면 27개(U-1). 24px 에도 못 미치는 것은 안내문 끝 ‘접기’(34×17)와 문장 속 글자 링크였다.
- 표: 정산 두 표·오늘 예산·결제수단 표는 390 폭에서 346~434px 을 옆으로 밀어야 했다(U-2). 공개 화면의 열 넷 이상인 표 넷도 32~128px(U-5).

## 고친 것

### U-1 좁은 화면에서 44px 에 못 미치는 조작 영역 (P3, 고침)
- 무엇(390·768 폭): 안내문 끝 ‘접기’ 34×17(열한 화면), 거래 탭 ‘홈으로’ 57×36, 조회 폼의 가계부·정산 방식 고르기 칸과 ‘조회’ 단추 40px(결제수단·키워드·정산), 키워드 삭제 단추 40×44(25개),
  캘린더 ‘닫기’ 48×36·달 이동 76×38(768 폭), 연간 리포트 ‘이전 해’ 34×40, 가계부 전환의 ‘내 계정·보안’·‘카카오 계정으로 본인 확인’ 42px, 모임 가계부의 ‘이름 확인 후 만들기’ 42px·‘정산’/‘기록’ 46×32,
  시작 가이드의 ‘보기’·‘하러가기’ 43px, 소비 분석의 보기 전환·‘예산 설정’ 40~42px, 로그인 화면의 ‘초대코드도 함께 입력’ 40px·‘문의’ 24×44, 정산의 ‘환급 연결 미리보기’ 125×21, 오늘 예산 표의 분류 링크 24×44.
- 고침(`src/modules/assets/accountbook-shell-css.js` 의 V22.9.124 블록, 1023px 이하에만): 위 요소의 최소 높이·폭을 44px 로. 데스크톱(1024px 이상) 배치는 그대로다.
  - ‘접기’ 는 글줄 높이를 늘리지 않으려고 문장 끝에 이어 붙인 단추라(V22.8 때 결정) 높이를 바꾸지 않고, 보이지 않는 덧칸(`::after`, 44px)으로 누르는 자리만 넓혔다.
  - 정산의 ‘환급 연결 미리보기’ 줄은 표식(`.abLinkRow`)을 달아 그 링크만 44px 높이로 했다.
- 다시 잰 값: 고친 화면 17곳의 390·768 폭에서 24px 미만 0, 44px 미만 0. 1440 폭의 값은 고치기 전과 같다.
- 그대로 둔 것: 문장 속 글자 링크(공개 화면 꼬리말의 이메일 15px, 글 머리의 운영자 링크 23px 등)는 U-12.

### U-2 정산·오늘 예산·결제수단 표가 휴대폰에서 옆으로 밀림 (P2, 고침)
- 무엇: 390 폭에서 ‘참여자별 정산’ 은 부담액·정산 상태가, ‘송금 횟수를 줄인 제안’ 은 금액이, ‘분류별 초과/주의’ 는 남음·게이지·상태가, ‘결제수단별 흐름’ 은 수입·상태가 화면 밖이었다
  (‘표는 좌우로 밀어서 전체 내용을 볼 수 있어요’ 안내와 함께 346~434px 을 밀어야 보임).
- 고침: 767px 이하에서 줄마다 카드로 쌓는다(셸 CSS `.abStackWrap`·`.abStackTable`). 칸 위에 그 열의 머리글을 보인다(`data-label`). 머리글 줄은 화면에서만 감춰 읽어 주는 도구에는 남는다.
  - 표식과 `data-label` 을 단 곳: `src/modules/features/settlement-ops-pages.js`(정산 두 화면의 두 표, 오늘 예산 표), `src/modules/features/budget-alerts-annual-goals.js`(분류별 줄), `src/modules/features/payment-methods-page.js`.
  - 쌓인 카드 안의 ‘빠른 등록’ 알약은 표 줄에 맞춘 음수 여백 때문에 머리글과 겹쳐서 그 여백을 없앴다.
- 768px 이상에서는 예전 표 그대로다.

### U-3 가로로 밀리는 표 상자의 포커스 표시가 약함 (P3, 고침)
- 무엇: 글쇠로 들어갈 수 있는 표 상자(`.tableWrap[tabindex]`, 결제수단별 흐름 표)에 들어가도 테두리 색만 조금 바뀌었다.
- 고침: `.tableWrap:focus-visible` 에 2px 윤곽선.

### U-4 목표 추가 폼의 다섯 칸 가운데 둘만 입력칸 위에 이름이 있음 (P3, 고침)
- 무엇: ‘이모지’·‘마감월(선택)’ 만 위에 이름이 있고 ‘목표 이름’·‘목표 금액’·‘월 납입액’ 은 자리표시가 이름을 겸했다. 두 칸 격자에서 이름 있는 칸과 없는 칸이 나란해 줄이 어긋나 보였다.
- 고침(`src/modules/features/budget-alerts-annual-goals.js`): 다섯 칸 모두 위에 이름을 두고 자리표시는 예시로(‘예: 여행자금’·‘예: 3,000,000’·‘예: 200,000’). 월 납입액은 비워도 되므로 ‘(선택)’ 을 붙였다.
  입력칸의 name 과 보내는 값은 그대로다(쉼표 든 금액은 서버가 예전부터 받는다).

### U-5 공개 화면의 넓은 표가 휴대폰에서 옆으로 밀림 (P3, 고침)
- 무엇: 열이 넷 이상인 표(개인정보처리방침의 처리 항목·위탁 표, /demo 의 예제 거래 표, 단톡방 안내의 정산 예 표)는 칸마다 최소 110px 이라 390 폭에서 32~128px 을 밀어야 했다.
- 고침(`src/modules/public/content-pages.js`): 600px 이하에서 줄마다 카드로 쌓는다. 표와 칸의 마크업은 그대로 두고 감싸개에 표식(`data-stack`)만 달며, 칸 위 머리글은 그 표에만 걸리는 CSS 로 만든다.
  규칙은 그런 표가 있는 화면에만 싣는다(첫 화면 36 KiB 예산, 다른 공개 화면의 바이트는 `.pubBrand` 16 B 만 늘었다). 공개 화면의 글자는 바꾸지 않았다.

### U-6 /demo 계산 입력칸이 13px 이라 iOS 가 화면을 확대함 (P3, 고침)
- 무엇: 입력칸 규칙은 16px 인데 공개 화면이 함께 받는 옛 스타일(`ab-uiux`)의 `font-size:inherit!important` 가 덮어 라벨 크기(13px)가 됐다.
- 고침: 더 좁게 가리키는 규칙으로 16px. /demo 에만 싣는다.

### U-7 공개 화면 머리의 서비스 이름 링크가 32px 높이 (P3, 고침)
- 고침: 최소 높이 44px(머리 높이는 그대로).

## 남긴 것

### U-8 글자 크기·굵기 눈금이 흩어져 있음 (P3, 남음)
- 홈 1440 폭에 글자 크기 20단(9·10·10.5·11·11.5·12·12.5·13·13.3·13.5·14·15·15.5·16·17·18·20·22·24.2·36), 굵기 10단. 홈의 글자 요소 가운데 68%가 굵기 700 이상이라(390 폭 100개 중 68, 1440 폭 192개 중 131) 굵기가 위계를 가르지 못한다. 11px 보다 작은 글자가 데스크톱 오른쪽 내역(날짜·건수·분류·결제수단 10~10.5px, ‘원’ 9px)과
  무지출 카드(요일·범례 10px)에 있다. 대비는 통과하지만 작다.
- 제안 눈금: 글자 11·12·13·14·16·18·20·24·36(아홉 단, 반 픽셀 없음), 굵기 400·600·700·800. 데스크톱 내역의 10~10.5px 은 11px 로.
- 남긴 이유: 눈금을 맞추는 일은 화면 전체의 밀도와 줄바꿈을 바꾼다. 디자인 지시서(V2 남은 단계)와 함께 출시 뒤에 한다.

### U-9 간격·모서리 값이 눈금 밖 (P3, 남음)
- 화면마다 간격 값 16~23가지, 그 가운데 4의 배수가 아닌 값이 12~16가지(5·6·7·9·10·11·13·14·15·18·22px 등). 모서리는 11px 과 12px 이 섞여 있다.
- 제안 눈금: 간격 4·8·12·16·20·24·32, 모서리 8·12·16·999.
- 남긴 이유: U-8 과 같다.

### U-10 아직 쌓지 않은 표 (P3, 남음)
- 잰 화면에 남은 것: 설정(전체 요약)의 분류 예산 표는 390 폭에서 13px, 오늘 예산 표는 768 폭에서 83px 을 표 상자 안에서 민다(767px 이하에서만 쌓는다).
- 이번에 재지 않은 화면의 표: 분석·리포트의 월별·분류 비교 표, 카드 혜택 표, 가져오기 미리보기 표(고르는 칸이 있음), 정산 완료 이력 표, 모임 가계부 목록 표(3열, 지금은 화면 안에 들어옴).
- 같은 표식(`.abStackWrap`·`.abStackTable` + `data-label`)을 달면 된다. 가져오기 미리보기는 고르는 칸 때문에 따로 봐야 한다.

### U-11 빠른 입력 시트의 입력칸은 자리표시가 이름을 겸함 (P3, 남음)
- 금액 칸의 자리표시가 ‘예: 12,000’ 뿐이다(위의 요약 칩에 ‘금액 · 미입력’ 이 있다). 내용 칸은 ‘내용 예: 점심, 쿠팡, 병원’.
- 입력칸 위 이름을 더하면 시트가 길어진다(지금도 844px 화면에서 ‘자세히’ 가 접힌다). 금액 칸 자리표시를 ‘금액 예: 12,000’ 으로 바꾸는 것부터 — 이 문구를 고정한 검사가 여럿이라 따로 한다.

### U-12 문장 속 글자 링크의 높이 (P3, 남음)
- 공개 화면 꼬리말의 이메일 링크 116×15(글자 10.5px), 글 머리의 운영자 링크 73×23, 로그인 화면 아래의 ‘문의’ 등. WCAG 2.5.8 은 문장 속 링크를 예외로 둔다.
- 꼬리말 글자를 12px 로 키우고 링크에 위아래 여백을 주면 된다. 꼬리말은 모든 화면의 HTML 에 들어 있어 바이트 예산(홈 35 KiB)과 함께 봐야 한다.

### U-13 휴대폰 화면 위쪽의 빈 띠 38px (P3, 남음)
- 달 이동 줄과 첫 카드 사이가 38px 이다(머리 아래 여백 12 + 본문 위 여백 14 + 카드 위 여백 12). 본문 위 여백을 4px 로 줄이면 28px 이 된다.
- 모든 휴대폰 화면의 세로 리듬이 바뀌므로 U-8·U-9 와 함께 한다.

## 폼 기준(기준 2)에서 확인한 것

- 빠른 입력: 금액·내용을 넣는 동안 아래 한 줄(aria-live)이 ‘저장하면 남는 예산 …’ 을 미리 보여 주고, 저장 단추는 금액과 내용이 있어야 켜진다. 오류 문구는 할 일을 말한다
  (‘금액이 둘 이상이에요 … 한 건씩 나눠 적어 주세요’, ‘외화 금액은 원화로 바꿔 적어 주세요(예: 커피 130000원)’).
- 예산 줄 편집(`client/lucian-d-budget.js`)은 칸을 떠날 때 검증하고 한글 조합 중에는 오류를 지운다.
- 저장 중 표시(aria-busy)·두 번 누름 막기·오류 알림(role="alert")은 이미 있다.

## 독립 검토 (2026-11-15)

Claude 하위 에이전트가 운영 번들과 나란히 대조했다(셸 화면 66가지를 폭 여덟 개에서 옛 스타일시트와 바꿔 끼워 요소 위치 대조, ‘접기’ 덧칸 240가지, 공개 51화면 118표, 응답 1,179개).
판정은 P1·P2 없음, P3 여섯 건이고 모두 반영했다.
- 목표 추가 폼의 입력칸이 이름 칸(label) 안으로 들어가며 700px 위에서 16px → 13px 로 줄었다(옛 스타일이 label 을 13px 로, 그 안의 입력칸을 inherit 로 둔다) → 어느 폭에서나 16px.
