- 원칙: 금액·날짜 읽기를 규칙으로 넓히지 않는다. 읽는 규칙(`src/modules/nlu/**`)은 그대로 두고, 저장 직전 안전망(`src/modules/kakao/request-guards.js` kakaoRecordGuardV229120 의 끝)에서 틀리게 저장될 꼴을 알아보면 저장하지 않고 되묻는다.
- 더한 가족(답은 모두 "…저장하지 않았어요." 로 시작하고 한 줄씩 다시 보내는 법을 알려 준다, 단추 [오늘기록]):
  - 금액 범위(‘2~3만원’·‘20~30’), 외화(‘$20’·‘30달러’·‘30파운드’ — 같은 글에 원화 금액이 있으면 무게 단위는 보지 않음), 낸 돈과 거스름돈, 할인·쿠폰·포인트 금액이 붙은 결제, 단가와 수량(‘4500원짜리 2잔’·‘개당’·‘한마리에’), 나눠 낸 돈(반띵·엔빵·더치페이·‘나눠 냄’ — 음식을 ‘나눠 먹음’ 은 아님), 총액과 내역이 함께(합이 맞아 해석기가 총액을 이미 뺀 꼴은 그대로 저장), 날짜가 둘 이상(‘3일 커피 4000 ⏎ 5일 택시 8000’).
  - 수입·지출 말이 읽힌 구분과 어긋날 때(‘지원금 30만원 입금됨’ 이 지출로, ‘환불 안 되는 티켓 99000 결제함’ 이 수입으로 읽히는 꼴): 기존의 섞인 구분 답과 같은 글로 되묻고 [지출로 기록]·[수입으로 기록] 단추를 준다. 단추는 그 말을 다시 보냈을 때 고른 구분의 한 건으로 저장될 때만 주고, 아니면 한 건씩 앞에 ‘지출’·‘수입’ 을 붙여 보내 달라고 안내한다.
  - 같은 뿌리의 꼴 넷: 기록마다 금액 바로 뒤 말이 읽힌 구분과 반대일 때(‘월급 250만원 들어옴 카드값 50만원 결제’ 가 수입 둘로, ‘중고 책 팔아서 12000원 받고 커피 4500 사먹음’ 이 지출 둘로 읽히는 꼴 — 여러 건은 단추 없이 한 건씩 보내 달라고 한다), 수입 한 건인데 금액에 붙은 낸 말로 끝날 때(‘네일아트 받음 현금 45000 냈음’), 지출 한 건인데 남이 주어로 돈을 준 말로 끝날 때(‘아빠가 차비 2만원 줌’), 수입 한 건인데 받은 돈으로 산 것일 때(‘용돈 받아서 커피 4500원 삼’).
  - 원 없이 적힌 10~99 가 다른 금액·물결표·세는 말과 함께 기록이 될 때(‘11~12월 주차비 두 달치 120000’ 의 11, ‘월급 300 상여 50’ 의 50): 한 자리 금액과 같은 글로 되묻는다. ‘사탕 50원’ 처럼 원을 붙인 수와 수 하나만 적힌 말(‘문구점 스티커 80’)은 그대로 저장한다.

### F-6 가져오기 표의 ‘12.000원’ 이 12원으로 읽힘 (P2, 고침)
- 무엇: 가져오기 표의 금액 칸 "12.000원"·"5.000" 이 12원·5원으로 읽히고 확인 표시 없이 기본 선택됐다. 카카오·빠른 입력은 같은 글을 12,000원으로 읽는다.
- 고침(`src/modules/import/flexible-import-parser.js`): 점 뒤가 0 세 자리 이상인 칸은 금액으로 읽지 않고 ‘금액 형식을 해석하지 못함’ 으로 되묻는다(‘12000.00’·‘12,000.0’ 은 예전처럼 12,000원).
- 머리줄 없는 표: 점이 찍힌 금액 칸(괄호·통화 표시·부호를 뗀 값이 ‘12.000’·‘1.200.000’ 같은 천 단위 점 꼴이거나, 예전 칸 읽기가 ‘12000.000’ 처럼 0 세 자리 이상의 꼬리로 받던 꼴)은 문장 해석으로 넘기지 않는다. 그 칸뿐이면 ‘금액 형식을 해석하지 못함’, 다른 금액 칸이 함께 있으면 ‘금액이 둘’ 로 되묻는다. 머리줄 있는 표와 결과가 같다.
  - 수정 도중의 결함: 2·3차 수정에서는 ‘(12.000)’·‘△12.000’ 이 환불 12원(확인 필요) 대신 지출 12,000원으로 바로 저장 대기에 올랐다(독립 검토가 찾아 4차에서 고침, 장면 45개로 고정).
  - 전화번호·환율·좌표처럼 점이 찍힌 다른 칸이 있는 줄, 값이 0 인 ‘0.000’ 칸이 있는 줄은 예전처럼 그 줄의 금액으로 저장된다.
- 바뀌는 것(되묻는 쪽으로): 머리줄 없는 표의 ‘₩1.200.000’ 은 예전에 1,200,000원으로 읽혔고 이제 되묻는다. ‘12.500원’·‘1.500’(무게)·‘3.141’ 같은 칸이 다른 금액과 한 줄에 있으면 예전에는 그 금액으로 저장했고 이제 금액이 둘이라고 되묻는다.
- 남음(고치기 전과 같음): ‘₩(12.000)’·‘KRW(12.000)’·‘–12.000’(en dash) 은 문장 해석이 음수 표시를 읽지 않아 지출 12,000원으로 읽힌다. 작은따옴표가 붙은 ‘'12.000’ 도 문장 해석으로 12,000원이다.

## 로그인·소유자 양도

### F-8 카카오 로그인이 같은 주소에서 15분에 20번까지이고 안내는 ‘1~2분’ (P3, 고침)
- 무엇: 카카오 로그인 콜백은 같은 IPv4 에서 15분에 20번까지였다. 성공해도 지워지지 않고 막힘은 15분인데 안내는 ‘1~2분’ 이었다. 주소를 함께 쓰는 곳(사무실·학교·통신사 공용 주소)에서 여럿이 가입하면 걸린다.
- 고침(`src/modules/auth/kakao-oauth.js`·`kakao-account-link.js`): 직접 누른 로그인의 한도를 50 으로(DB 함수의 상한), 자동 로그인(화면을 열 때 조용히 시도하는 길) 칸은 20 그대로. 막힘 안내는 ‘15분쯤 뒤’. 시도 제한 기능 자체가 응답하지 않을 때는 ‘잠시 후 다시’ 로 따로 안내한다.

### F-9 소유자 양도에 본인 확인이 없음 (P2, 고침 — 사용자 결정 2026-11-16 "소유자 양도 재확인도 이번에 넣고")
- 무엇: 소유자 양도는 세션 쿠키만으로 됐다. 소유자가 로그인해 둔 기기를 다른 구성원이 쓰면 자기에게 양도한 뒤 가계부를 지울 수 있었다(삭제에는 본인 확인이 있다).
- 고침(`src/modules/my/members-page.js`·`auth/identity-reauth.js`·`auth/kakao-oauth.js`·`my/households-lifecycle.js`): 양도 전에 삭제와 같은 본인 확인을 받는다 — 로그인 비밀번호, 또는 카카오 계정 본인 확인(5분 유효). 확인 표는 용도를 서명에 넣어 삭제용 표로 양도하거나 양도용 표로 삭제할 수 없다. 역할 재확인·부분 실패 복구는 예전 그대로다.
- 양도 칸의 네 모양:
  - ① 비밀번호가 있는 소유자: 비밀번호 칸 + [소유자 양도](카카오 로그인도 있으면 ‘또는 카카오 계정으로 본인 확인’).
  - ② 카카오 로그인만 있는 소유자: 카카오 본인 확인 뒤 양도 단추가 열린다. 카카오톡 안의 브라우저에서는 카카오 본인 확인이 열리지 않아 "Chrome·Safari에서 ‘카카오 로그인’으로 로그인한 뒤 … 눌러 주세요" 를 덧붙인다.
  - ③ 카카오 확인을 마친 뒤: "카카오 계정 본인 확인 완료 · 5분 동안 유효" + [소유자 양도].
  - ④ 채팅으로만 써 온 소유자(단톡방 가계부의 첫 호출자 등): 카카오 1:1 채팅에서 ‘웹 가계부 열기’ 로 웹 연결 코드를 받아 [웹 연결 코드 넣기] 에 넣고, 이어지는 ‘내 계정·보안’ 에서 5분 안에 로그인 이름과 비밀번호를 정한 뒤 그 비밀번호로 양도한다.
- 알려진 제약:
  - ④ 의 확인 강도는 ‘소유자의 카카오톡 1:1 채팅에 접근할 수 있는가’ 다. 채팅으로만 쓰는 사람에게는 카카오톡이 유일한 신원이라 더 강한 수단이 없다(가계부 삭제도 같다).
  - ④ 에서 비밀번호를 정하면 다른 기기의 세션이 끊기고, 그 뒤 새 브라우저에서 단톡방의 가계부 단추를 누르면 홈이 바로 열리지 않고 로그인 이름을 묻는다(V22.9.118 S-2 규칙, 바꾸지 않음). 양도 칸에 "저장하면 다른 기기·브라우저는 로그아웃되고, 그 뒤 로그인돼 있지 않은 브라우저에서 단톡방의 웹 가계부 단추를 누르면 홈 대신 로그인 이름과 비밀번호를 먼저 물어요." 를 적었다.
  - 웹 연결 코드는 비밀번호가 이미 있는 계정에도 5분 본인 확인 표를 준다(예전부터, 이 판은 바꾸지 않음). 즉 1:1 채팅 접근이 곧 비밀번호 변경 권한이다.
  - 강한 로그인 행이 없는 옛 `local_web:` 소유자는 비밀번호 칸이 보이지만 어떤 비밀번호도 통과하지 못한다. 삭제는 예전부터 같은 막다른 길이었고, 이 판부터 양도도 같다(그런 계정은 다시 로그인할 수 없어 남은 세션으로만 들어온다 — 운영에 있는지는 확인하지 않았다).
  - ④ 는 단톡방과 1:1 채팅의 봇 사용자 키가 같다는 전제 위에 있다(기존 방 답 V22.9.102 J-12 와 같은 전제). 운영에서 사람이 확인한 적은 없다 → 배포 뒤 사람 확인.
- 가계부 영구 삭제 칸의 채팅 소유자 안내도 같은 길로 맞췄다(예전 안내 ‘내 계정·보안 열기’ 는 막다른 길이었다). 다른 상태의 삭제 칸은 바이트가 같다.
- 로그인 수단을 확인하지 못하면(읽기 실패) 양도·삭제 칸은 "로그인 수단을 지금 확인하지 못했어요. 잠시 후 이 화면을 새로고침해 주세요." 만 보인다. 카카오톡 인앱의 ① 칸에서는 열리지 않는 카카오 단추를 뺐다(삭제 칸 ① 의 같은 단추는 예전 그대로다).
- 출시 뒤 후보: 비밀번호를 정하지 않고 웹 연결 코드 자체를 양도 확인으로 받기(F-38).

### F-15 로그인 쪽 작은 결함 다섯 (P3, 고침)
- ① 본인 확인(삭제·양도·계정 재확인·비밀번호 변경)이 장애·시도 제한을 ‘비밀번호가 맞지 않습니다’ 로 안내하던 것 → ‘시도가 많아 잠시 막혔습니다(15분쯤)’ 와 ‘지금 확인하지 못했습니다’ 를 따로 안내한다. 확인하지 못하면 늘 거절이다.
- ② 로그인 이름 로그인의 429·503·500 화면이 돌아갈 주소를 잃던 것 → 모두 return_to 를 싣는다.
- ③ 로그인·가입은 됐는데 일반 오류 문장이 보이던 길(없는 초대코드, 가입 뒤 초대 참여 실패) → "로그인은 완료되었습니다. 입력한 초대코드는 찾지 못했습니다. …" 처럼 사실대로.
- ④ 계정을 바꿔 로그인하면 앞 계정의 설정 안내 띠 쿠키가 남던 것 → 다른 계정으로 세션이 바뀔 때 지운다(같은 계정이면 그대로).
- ⑤ 가입 이름 검사의 와일드카드: `_`·`%`·`\` 를 글자로 다루고, 옛 이름 대조는 50행까지만 읽어 같은 이름만 막는다(50행이 차면 ‘이미 사용 중’ 으로 닫는다).

### F-26 백업 복구가 다른 가계부에 기록을 옮겨 담음 · 올릴 수 있는 크기 안내가 틀림 (P2, 고침)
