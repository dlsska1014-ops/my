## 무엇이 바뀌나

- [고치기]: 저장을 막는 까닭이 있으면 그 칸으로 간다 — 공용 입력 컨트롤러가 저장 단추 아래 안내와 같은 차례(외화·금액 둘·구분·금액·날짜·내용)로 까닭을 적고, [고치기]와 해석 결과 한 줄은 안내 글을 읽지 않고 그 값을 본다. 금액이 둘이면 한 줄 입력, 외화·금액이면 금액 칸, 구분이면 구분(숨은 라디오라 초점이 보이지 않으므로 구분 묶음에 테두리), 날짜면 날짜, 내용이 비면 내용, 막는 까닭이 없으면 분류. 접힌 3층은 그 칸이 3층에 있을 때만 연다. 한 줄 입력 아래 안내는 이 줄이 대신하므로 숨긴다(스크립트가 없으면 그대로 보인다).
- 3층(접힌 ‘자세히’): 날짜·사람·결제수단·분류, 그리고 맨 끝에 금액 단축 단추(+1천 … 지우기). 단추를 눌러도 초점은 그 단추에 남고(시트가 위로 뛰거나 휴대폰 자판이 뜨지 않는다) 결과는 단추 곁의 결과 줄에 적는다(‘금액 13,000원’·‘금액을 지웠어요’·더할 수 없는 까닭 — 읽기 프로그램도 읽는다). 금액 안내(형식·예산 넘침)는 금액 칸 바로 아래에 남는다(접혀도 보인다).
- 날짜 글: ‘자세히’ 접힌 줄(서버가 그리는 첫 글과 화면 스크립트가 다시 쓰는 글), 해석 결과 한 줄, 시트 머리 설명, 날짜가 엇갈렸다는 안내가 같은 꼴이다 — ‘오늘’·‘어제’·‘7월 10일’·다른 해는 ‘2025년 12월 31일’. 오늘·어제는 한국 날짜로 센다(기기 시간대·한국 자정 직후 포함).
- 방 전용 보기: 알림 API 가 열 수 없는 화면의 링크에 closed: true 를 붙이고, 알림 패널·홈 배너가 그 링크를 서버의 링크 표시와 같게 흐리게·aria-disabled·title 로 표시한다(보통 세션의 답은 그대로). 입력칸이 없는 시트(방 전용 보기·조회 전용)는 초점을 [닫기]로, 머리 설명은 비운다(‘거래일을 확인한 뒤 저장해 주세요.’ 가 맞지 않는다).
- 첫 사용 안내: 캘린더 단계가 ‘최근 내역’ 머리의 캘린더 링크를 찾는다.
- 그대로인 것: 칸 id·저장하는 값·초안(sessionStorage)·초점 가둠·Esc·금액이 틀리면 저장을 막고 금액 칸으로·예산 넘침 안내, 말을 읽는 규칙(금액·날짜를 넓히지 않았다)·권한·쿠키, 카카오 답, 소비 분석 화면(R3).

## 발견

### Q-1 빠른 입력 시트가 빽빽함 (P3, 고침)
- 바탕: 390폭 시트 787px, ‘기록 저장’ 901~947px(첫 화면 밖). 해석 칩 다섯이 세 줄을 차지했고 금액 단축 단추·자주 쓰는 칩 두 줄이 그 아래에 있었다.
- 고침: 3층(위 ‘무엇이 바뀌나’). 390폭 시트 501px, ‘기록 저장’ 777~823px(작업 지시서 수용 기준 — 키보드 없이 첫 화면에 ‘기록 저장’ 까지). 해석 칩 줄과 안내 194px → 해석 결과 한 줄 44px, 자주 쓰는 칩 102 → 50px. 1280폭 시트 683 → 503px(‘기록 저장’ 692~740px).
- 3층을 펼치면 시트가 길어진다(390폭 약 970px — 시트 안에서 넘긴다). 펼친 사람은 날짜·결제수단을 고치려는 사람이다.

### Q-2 큰 금액 칸의 높이·숫자 폭 (P3, 고침)
- 바탕: 큰 금액 칸의 글자는 24px·굵기 800(앞 판)이었지만 높이는 46px 이고 숫자 폭이 글자마다 달랐다.
- 고침: 56px·숫자 폭 고정. 옛 UI 런타임의 입력칸 규칙(.abV2281 input — 최소 높이 46px·숫자 모양 inherit)과 휴대폰 앱 화면의 칩 줄 바꿈(.abMobileAppSurface .chipRow)이 우선 표시라, 홈 스타일시트의 #add 안 id 규칙이 같은 세 속성만 우선 표시로 이긴다(우선 표시 상한 380 → 384(칩 초점 테두리 1회 포함) — validate-design-uplift-v22984).

### Q-3 PC 홈 안의 빠른 입력 칸 높이 (P3, 남음)
- 시트를 열지 않은 PC 홈 안의 빠른 입력 칸은 542 → 554px 이다(큰 금액 칸 56px). 이 칸은 시트를 열 때만 빠른 입력 자산(해석 결과 한 줄·금액 단축 단추)을 싣는다 — 예전에도 해석 칩은 시트에서만 보였다.
- 다음 행동: 작업 지시서 9단계(PC 2단·예산·첫 화면 — V22.9.140)에서 PC 입력 칸의 자리와 높이를 정한다.

### Q-4 금액 단축 단추를 누를 때마다 초점이 금액 칸으로 (P2, 고침)
- 독립 검토가 창 없는 Chrome(390×844)에서 재현했다: ‘자세히’ 를 열고 [+1만] 을 누르면 초점이 금액 칸(시트 위 16px — 화면 밖)으로 갔고, 금액이 틀린 상태에서 [+1천] 을 누르면 안내도 화면 밖이었다. 바탕은 금액 칸과 단추가 함께 보였다. 휴대폰에서는 사용자 동작 안의 초점 이동이라 자판이 떠 단추가 가려진다(추론).
- 고침: 초점은 누른 단추에 남고, 결과는 단추 묶음 안의 결과 줄(role=status — 읽기 프로그램도 읽는다)에 적는다. 금액을 손으로 바꾸면 결과 줄을 숨긴다. 금액 칸 바로 아래의 형식·예산 안내는 그대로다.

### Q-5 [고치기]가 저장을 막는 까닭을 건너뜀 (P2, 고침)
- 재현(독립 검토): 금액 칸에 12000 만 넣으면 저장 단추가 꺼지고 안내는 ‘내용을 적으면 저장할 수 있어요’ 인데 [고치기]는 3층을 열고 분류 칸으로 갔다. ‘커피 4500 점심 9000’ 은 줄이 첫 금액(4,500원)만 적어 다 된 기록처럼 보였고 [고치기]도 분류 칸으로 갔다.
- 고침: 컨트롤러가 까닭을 값으로 적고 [고치기]·줄이 그 값을 본다. 금액이 둘이면 한 줄 입력, 외화·금액이면 금액 칸, 구분이면 구분, 날짜면 날짜, 내용이 비면 내용, 막는 까닭이 없으면 분류. 줄은 ‘내용 미입력’·‘금액 둘 이상’ 을 적는다.
- 앞 코드의 ‘구분 확인 필요’ 는 컨트롤러 안내 글의 낱말(‘수입 또는 지출을 직접’)에 기댔다 — 금액 둘·외화 안내가 앞서면 결제 취소 문장이어도 ‘지출’ 이었다. 이제 안내 글과 상관없다.

### Q-6 [고치기]가 늘 3층을 열고 구분 초점이 안 보임 (P3, 고침)
- 재현(독립 검토): 결제 취소 문장에서 [고치기]를 누르면 1층의 구분으로 보내면서도 3층을 열어 저장 단추를 밀어냈고, 숨은 라디오라 :focus-visible 이 서지 않아 초점 표시가 없었다(바탕의 ‘구분’ 칩도 숨은 라디오로 보냈다).
- 고침: 3층은 그 칸이 3층일 때만 열린다. 구분으로 보낼 때 구분 묶음에 강조색 2px 테두리를 단다.

### Q-7 [고치기]의 먹지 않는 굵기 (P3, 고침)
- 옛 UI 런타임의 단추 규칙(굵기 600, 우선 표시)이 이겼다. 다른 단추와 같은 600 이 맞다고 보고 선언을 지웠다.

### Q-8 자주 쓰는 칩의 초점 테두리 잘림 (P3, 고침)
- 공통 초점 규칙(3px·바깥 3px, 우선 표시)을 가로로 넘기는 칩 줄이 잘랐다 — 테두리의 위·왼쪽 끝이 줄보다 6px 바깥이었다(390·1280 모두). 앞 판의 두 줄 칩도 같았다.
- 고침: 칩 줄 안의 칩만 테두리를 안쪽(-3px)에 그린다. 다시 재니 잘림 0, 밝은·어두운 테마 모두 보인다.

### Q-9 입력칸이 없는 시트의 머리 설명 (P3, 고침)
- 날짜 칸이 없어 날짜 확인이 실패한 것으로 처리돼 ‘거래일을 확인한 뒤 저장해 주세요.’ 가 나왔다(앞 판부터 같은 글).
- 고침: 입력칸이 없으면 설명을 비운다.

### Q-10 기기 시계와 서버 오늘 (P3, 남음)
- 해석 결과 한 줄·시트 머리·‘자세히’ 줄(화면 스크립트)은 기기 시계로 한국 날짜의 오늘·어제를 센다. 입력 컨트롤러의 날짜 해석(‘어제 점심’)과 서버가 그리는 첫 글은 서버의 오늘을 쓴다. 기기 시계의 날짜가 서버와 다르면 글이 ‘7월 15일’ 처럼 날짜로 나온다 — 저장되는 날짜 값은 그대로다(픽스처 확인에서도 보인다: 브라우저는 실제 날짜, 서버 픽스처는 2026-07-15).
- 다음 행동: 다음 입력 화면 판에서 화면 스크립트가 서버가 준 오늘을 쓰게 할지 본다.
