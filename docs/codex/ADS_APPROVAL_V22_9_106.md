## 광고 및 데이터 범위

두 광고 네트워크의 허용 목록은 위 6개 공개 글이다. 유효한 발급 슬롯, 정확한 HTTPS 정본 URL, 실제 표시된 문서라는 조건을 모두 만족해야 SDK를 한 번 불러온다. 개인 가계부·입력표·허용 목록 밖 문서·매개변수·프래그먼트·미리보기 호스트·숨김/사전 렌더링 문서에서는 시작하지 않는다. 광고 영역은 초기 상태와 SDK 오류 상태에서 숨긴다.

계산표에는 광고·분석·외부 스크립트가 없고 응답 CSP의 `connect-src 'none'`으로 외부 연결을 차단한다. 입력을 브라우저 저장소에 넣지 않는다. 공개 GET·HEAD는 HTTPS 정본으로 이동하며 카카오 POST 처리는 바꾸지 않는다.

별도 tools 저장소는 일반 비민감 도구 6개만 하단 광고 후보로 남기고 건강·재정·양식·개인 입력 화면은 제외했다. 도구의 법정 수치·건강 설명·암호 생성 실패·반복 FAQ도 보완했다. 앱 Worker만 배포하면 tools 변경은 반영되지 않는다.

## 다음 심사에 필요한 운영 증거

1. 검증된 변경을 운영에 반영한 뒤 실제 버전·확인 시각·후보 URL·신규 자산을 기록한다.
2. 최신 AdSense 콘솔의 사이트 사유와 재검토 가능 상태를 확인한다. 제공된 회신으로 거절 사유는 확인했지만 콘솔의 현재 요청 가능 상태는 확인하지 않았다.
3. 실제 이용 보고서에는 조회 기간·시간대·호스트·후보 URL·시험/봇 제외 조건을 붙인다. 미측정 값을 추정하거나 임의의 방문자 합격선을 만들지 않는다.
4. AdFit 신청 주체·도메인 관리 관계·운영 기간·실제 이용 자료를 연결한다. 기존 제출본을 확보하지 못하면 ‘이전 제출보다 달라졌다’는 비교 대신 현재 확인된 사실만 적는다.
5. 실제 사용 과제와 광고 계정 설정·동의 설정·SDK 실행을 확인한다. 광고 발급 전 가능한 코드 검사와 발급 후 활성 전 검사를 구분한다.

- [AdFit 운영정책](https://adfit.kakao.com/web/html/use_kakao.html)은 소유관계·콘텐츠·트래픽·운영 지속성·광고 적합성을 종합 검토한다고 설명한다.
