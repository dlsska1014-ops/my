## 원인과 결함 구분

P1의 금액 변환·저장과 쉼표 변경 시 커서 이동은 선행 결함입니다. 기존 mobile-home 인라인 formatter와 legacy formatter가 숫자 이외 문자를 삭제하고, 입력 컨트롤러가 Number 범위만 확인했습니다. 실제 Chrome에서는 capture 리스너가 예약한 마이크로태스크가 뒤 target 리스너보다 먼저 실행될 수 있어 A의 원문 복원·오류 표시 뒤에 포맷과 유효성 해제가 일어났습니다. A의 새 형식 오류 차단이 실제 입력에서는 완료 기준을 충족하지 못한 것으로 기록합니다.

P2는 A 신규 결함입니다. 파싱 전에 칩을 그렸으며 수동 분류에서는 비동기 추천이 생략되어 뒤 완료 이벤트가 발생하지 않았습니다. 정상 통화 입력도 정규화 전에 그린 ‘형식 확인’ 칩에 남았습니다.

## 수정 구조

공용 quickAmountFieldState는 원문을 검증하고 허용 통화 표현·숫자 구분 쉼표만 정규화합니다. 문자·부호·소수점이 있는 원문은 보존합니다. 정규화·필드·유효성·숫자 순서 기준 커서를 동기 처리하며 입력 컨트롤러가 미리보기와 수동 표식을 반영합니다. 각 파싱·수정·초안·추천 완료 경로 끝에서 ab:quick-update를 동기 통지합니다. A는 완료된 필드를 읽어 칩·예산 안내를 그리며 별도로 금액 유효성을 해제하지 않습니다.

기존 destructive 인라인 formatter와 제출 시 쉼표 삭제를 제거했습니다. 서버는 원래부터 쉼표가 있는 금액을 받으므로 제출값을 바꾸지 않습니다. IME 조합 중에는 금액을 다시 쓰지 않으며 확정 뒤 같은 검증 경로를 사용합니다. 한 줄 입력의 IME 중 Enter도 해석하지 않습니다.
