# Lucian D 예산 구현 계약

시작 기준은 V22.9.51이며 구현 작성자는 root 한 명입니다. 원본 777개 파일과 HEAD bundle, 미커밋 diff, 목록·해시는 `D:/CodexRecovery/lucian-d-budget-20261015-142215`에 보존했습니다. 원본과 승계본의 모든 파일 해시가 일치합니다. D0와 D 미리보기만 구현하며 가져오기·C 비교·정기 반영·DB 정의·외부 설정·Git 게시는 범위에 포함하지 않습니다.

## D0 집계 정책 (소스 수정 전 확정)

- 예산의 이름 비교에는 현재 저장 경계의 `normalizeText`를 사용합니다. 공용 정규화 함수는 변경하지 않습니다.
- `LEGACY_CATEGORY_SPLITS`에 실제 존재하는 다섯 매핑만 사용합니다. 식비는 외식·배달·편의점을 포함하고 장보기·카페/간식을 포함하지 않습니다. 교통/차량은 교통·택시·주유/충전·차량관리를 포함합니다. 교통 자체는 독립 분류입니다.
- 상위 이름 자체에 기록된 거래도 포함합니다. 사용자 정의 분류도 같은 이름 규칙을 적용하며, 상위 이름과 정규화 이름이 같으면 같은 호환 묶음으로 해석합니다. 분류 정의를 조회하여 의미를 바꾸거나 기존 행을 이관하지 않습니다.
- 상위·하위 예산이 함께 있으면 행별 사용액은 중복될 수 있습니다. 전체 예산 대상 지출은 해당 거래의 합집합으로 한 번만 계산합니다. 예산 배분액은 사용자가 입력한 금액의 합계를 유지합니다.
- 양수 분류예산 합계가 있으면 기존 `__total`보다 우선합니다. 종류별 양수 수입이 있으면 `__income`을 중복 합산하지 않습니다.
- 홈·사용 내역·예산 안내·카카오 피드백과 분석에 전달하는 대상 분류 데이터는 같은 규칙을 사용합니다. 분석 클라이언트와 비교 기능은 변경하지 않습니다.

수정 전 합성 거래에서 전체 지출 64,500원 중 네 예산 행의 합집합은 50,500원이어야 합니다. 현재 코드는 16,500원으로 계산했습니다. 식비 자체 1,000원 외에 외식 12,000원·배달 13,000원·편의점 2,000원을 누락했습니다. 독립 교통 3,000원과 교통/차량 자체 500원도 각자의 의미로 보존합니다. 수정 전 기록은 복구 폴더의 `before-evidence/report.json`에 있습니다.

## 입력·저장 계약

- 빈 금액은 0원이며 양수 행만 전체 교체 계획에 포함합니다. 지출 이름이 비면 양수 금액도 제외하지만 잘못된 금액은 이름과 무관하게 먼저 거절합니다.
- 금액은 원 단위의 안전한 정수이며 한 행의 상한은 기존 20억원입니다. 소수 원·부호·지수·잘못된 쉼표를 변환하지 않습니다. 공용 스캐너의 정확한 정수 단위 환산을 그대로 주입하여 50만·1.5만원·0.5천원·0.29백원을 유지합니다.
- 이름은 앞뒤 공백 제거 후 수입 60자·지출 80자를 사용하며, 자른 뒤 생기는 끝 공백도 기존 RPC와 같이 제거합니다. 실제 저장 이름을 표시하고 이 최종 이름으로 예약 이름과 중복을 검사합니다. 수입의 빈 이름은 현재 행 순서에 따라 월급·상여/성과급·부수입·기타수입·수입N을 적용합니다.
- 정규화한 같은 종류·같은 이름·같은 양수 금액은 한 번만 반영합니다. 다른 양수 금액은 전체 저장을 거절합니다. 수입과 지출의 중복 키를 별도 네임스페이스로 구분하여 기존 정규화 접두사 충돌을 해결합니다.
- 새 저장 경계 검증으로 이름·금액 배열 불일치, 원시 입력 합계 200행 초과, 예약 지출 이름 `__total`·`__income`·`__income:*`을 거절합니다. 기존의 최종 양수 고유 계획 100행 제한과 구분합니다.
- 기존 일반 예산 행은 정규화 이름이 같더라도 모두 편집기에 표시합니다. 사용자가 중복 충돌을 해결하기 전에 저장된 행을 조용히 생략하지 않습니다.
- 특수 총액 행을 편집 합계에 숨겨 더하지 않습니다. 전체 교체 시 제외된다는 사실과 현재 저장 요약을 별도로 표시합니다. 실제 수입으로 예상 수입을 대체하지 않습니다.
- 인증·관리 권한·CSRF·명시적 가계부와 월 범위·엄격 조회·fingerprint·월별 잠금·쓰기 직전 최신성·기존 교체 RPC를 유지합니다. 실패 시 원문과 원래 fingerprint를 재표시하며 오래된 토큰을 최신 토큰으로 바꾸지 않습니다. 결과 불명확은 성공으로 안내하지 않습니다.
