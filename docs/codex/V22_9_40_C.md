## 결정

1. **C1 — 고르면 바로 이동하지 않는다.** iOS 휠처럼 고르는 중에도 `change` 가 날 수 있고, 값을 바꾸는 것만으로 화면이 바뀌면 WCAG 3.2.2(입력 시 맥락 변경)에 걸린다. 그래서 "이동"을 남기되, JS 화면에서는 다른 달을 고른 뒤에만 보이게 했다(처음에는 단추 셋 — `‹`·`2026년 7월 ▾`·`›`). 단추 이름은 보이는 글자를 품는다("기준 월 2026년 7월, 다른 달 고르기" → 고른 뒤 "…, 이동 단추를 눌러 적용").
2. **C1 — 단추는 JS 가 만든다.** JS 없는 화면에 죽은 단추가 남지 않는다. 월 입력은 같은 칸 밑에 투명하게 남아 폼 제출과 선택기 위치를 맡고 탭 순서·보조기기 트리에서 빠진다. 헤드리스 Chrome 에서 마우스·Enter 로 연 선택기를 닫은 뒤에도 초점이 단추에 남는 것을 확인했다. `autocomplete=off` 는 뒤로 가기 때 고른 값만 되살아나 단추 글자와 어긋나는 것을 막는다.
3. **C1 — 핀은 모두 그대로.** 모바일 '이번 달' 링크의 `min-height:36px` 규칙은 `validate-screen-audit-fixes-v22918` 이 글자 그대로 고정하므로 지우지 않고, 같은 미디어 블록 안 뒤에서 44px 로 덮었다. `/reports` 의 `.btn, button{color:#fff!important}` 때문에 기준 월 단추 글자색만 `!important` 다.
4. **C4 — 원안(내비 JS 자산으로 이동)은 보류, 홈만 머리로 옮겼다.** 원안의 보류 조건이 둘 다 맞았다: 내비 JS 주소(`accountbook-nav-v22937.js`)를 고정한 검사기가 17개이고 그중 `validate-adsense-v2-v22817`(B 소유)가 4줄이다. 내비 JS 판을 올리면 옛 바이트를 `historical-runtime-assets.js`(소유 밖)에 보관해야 한다. 또 로그인 화면(`/my`)의 유일한 데이터 블록이 이 규칙이라 `validate-ux-principles`(A 소유)의 "login page carries its non-JavaScript script data block" 가 깨지고, 내비 JS 가 없는 공개 화면은 규칙을 잃는다. 대신 HTML 바이트 예산이 빠듯한 홈만 같은 규칙을 `Speculation-Rules` 머리로 받는다. 머리 규칙 파일은 cors·같은 출처 자격으로 받고, MIME 이 `application/speculationrules+json` 이어야 하며, CSP 는 이 파일을 막지 않는다(HTML 표준 7.6.3·7.6.5). 원안 설계는 "남긴 항목" 1.
5. **C4 — prefetch·moderate 는 넣지 않았다.** `validate-speculation-rules-v2297` 의 보호 기준이 "conservative 만 — moderate/eager 는 누르지 않은 링크도 열어 무료 한도 조건을 깬다"이다. Chrome 문서도 모바일 `moderate` 가 2025-08 부터 화면 휴리스틱(스크롤 멈춘 뒤 500 ms, 앵커 크기 조건)으로 누르지 않은 링크를 미리 받는다고 적는다. 개인 화면은 `no-store` 지만 speculation prefetch 는 HTTP 캐시 밖 메모리에 두므로 받을 수는 있다 — 받는 순간 홈 기준 DB 8회가 나간다는 점이 막는 이유다.
6. **C2 — 줄임 이름 `text-wrap` 을 쓰지 않았다.** `text-wrap:balance` 는 `text-wrap-mode` 까지 `wrap` 으로 되돌려 명시도가 높으면 `.topLine h1{white-space:nowrap;text-overflow:ellipsis}` 를 이긴다(홈 머리 제목이 두 줄로 터진다). 긴 이름 `text-wrap-style` 만 쓰면 nowrap 은 그대로다(헤드리스 Chrome 계산값 `text-wrap-mode:nowrap` 확인). 모르는 브라우저(Chrome 130 미만 등)는 무시한다.
7. **C2 — 글상자 높이는 공유 문구·읽기 전용만.** 가져오기 붙여넣기 칸은 행 수 기준 크기를 그대로 둔다. `/reports` 공유 문구는 지금까지 `.abV2281 textarea{min-height:46px!important}` 탓에 74 px 상자 안에서 16줄을 스크롤했고, 이제 내용 높이(470 px, 최대 506 px@844 px 화면)로 다 보인다. 그만큼 모바일 `/reports` 가 397 px 길어졌다.
8. **C2 — 창·팝오버 전환은 지원 확인 안에서만.** 등장은 `@supports (transition-behavior:allow-discrete)`, 닫힘(display·overlay)은 `@supports (overlay:auto)` — overlay 를 모르는 브라우저는 닫힐 때 맨 위 층에서 먼저 빠져 제자리에 비친다. 모두 `@media(prefers-reduced-motion:no-preference)` 안이고, 줄이기를 켜면 기존 전역 규칙(`transition-duration:1ms`)과 함께 즉시 열리고 닫힌다(헤드리스 Chrome 계산값 확인).
9. **C2 — 옛 셸 주소(v22937)는 보관하지 않는다.** V22.9.37 의 CSS 관례("옛 CSS 주소는 더 내려가지 않는다")를 따랐다. 개인 HTML 은 `no-store` 라 옛 주소를 부르는 화면이 남지 않고, Early Hints(C3)는 이번 판에 처음 생기므로 옛 주소를 가리키는 캐시된 힌트도 없다. 보관을 실제로 해 보니 Worker 가 202 KB 늘고, 원본 전체를 세는 검사기 3개(`validate-motion-scale-v22912` 게이지 4→5, `validate-month-reset-brand-icon-v22879` 3→4, `validate-desktop-cursor-v22895` 2→4)가 같은 CSS 를 두 번 셌다. 옛 주소는 404 이고 새 검사기가 그것을 고정한다.
10. **소유 밖 파일.** 처음에는 `asset-responses.js`(셸 ETag 한 줄)와 `validate-adsense-v2-v22817.mjs`(B 소유, 셸 주소·ETag 단언 4곳)를 통합 요청으로만 두었으나, 이 두 곳이 없으면 셸 ETag·주소를 보는 검사기 19개가 이 브랜치에서 실패했다. 조정자 지시에 따라 두 파일을 커밋에 넣었다 — adsense 검사기는 셸 주소 단언만 바꿨고 B 의 소스 금지 단언과 내비 JS 주소는 건드리지 않았다.
