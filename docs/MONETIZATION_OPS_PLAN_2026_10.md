## 2. 수익화: 사용자가 돈을 내지 않는 구조

### 2-1. 현재 상태 (코드 기준)

- AdSense 게시자 ID `ca-pub-3546469870344416`, `ads.txt` 정상, 공개 14쪽에 소유권 메타 태그. 사이트 심사는 2026-10-01 요청 뒤 "검토 중".
- **코드는 심사 모드로 잠겨 있습니다.** `validate-adsense-v2-v22817`가 다음을 강제합니다: 광고 런타임(`adsbygoogle`)·슬롯·광고 쿠키 없음, CSP 에 광고 호스트 없음, 소스에 `ADSENSE_ENABLED`·`ADSENSE_AUTO_ADS` 문자열 없음. 운영 변수 `ADSENSE_ENABLED`·`ADSENSE_AUTO_ADS`는 존재하지만 코드가 읽지 않습니다.
- 즉 **승인이 나도 광고는 저절로 켜지지 않습니다.** "광고 켜기" 판(아래 2-3)을 따로 만들어 배포해야 합니다.
- 제휴·추천 UI 는 `renderAffiliateCard`(생활비 팁 카드)만 있고 외부 링크·수수료 연결은 없습니다.

### 2-2. 어디서 얼마나 나오는가 (현실적인 기대치)

| 수단 | 기대 단가 | 조건·위험 |
|---|---|---|

### 2-3. "광고 켜기" 판 설계 (AdSense 승인 뒤 바로 배포할 수 있게 지금 준비)

1. 새 변수 하나(`ADS_MODE=review|live`, 기본 `review`)로 게이트. 운영 변수는 승인 뒤 대시보드에서 바꿉니다(코드 재배포 없음).
2. `live` 에서만: 공개 14쪽 + 로그인 뒤 **콘텐츠 화면**(`/reports`, `/my/analysis`, `/annual`, 가이드 류)에 광고 슬롯 1~2개, CSP 에 `pagead2.googlesyndication.com` 등 허용, 쿠키 정책 문구 갱신.
3. 다음 화면은 **광고 금지**: `/app` 홈·빠른 입력·거래 목록, 모든 폼, 로그인·가입, 관리자·운영 화면. 버튼 44px 안에 광고 금지(오클릭 방지).
4. 검사: `validate-adsense-v2-v22817`를 "review 모드 = 기존 단언 전부, live 모드 = 슬롯은 허용 화면에만·금지 화면에는 없음·CSP"로 확장.
5. 승인 뒤 첫 2주는 자동광고(Auto ads) 끄고 수동 슬롯만. 자동광고는 입력 화면까지 침범합니다.
6. AdSense 와 애드핏을 같은 화면에 겹치지 않게 배치(공개 페이지=AdSense, 로그인 콘텐츠 화면=애드핏부터 시험 등)하고 두 달 뒤 RPM 으로 정합니다.

### 2-4. 수익을 키우는 제품 쪽 일 (돈 안 받고 수익을 올리는 실제 지렛대)

- **주간·월간 생활비 리포트**(V22.9.38): 매주 돌아올 이유. 리포트는 글·해석이 있는 콘텐츠 화면이라 광고 정책에도 맞습니다.
- **공유 배지·카드**: 리포트 요약 이미지를 카카오톡에 공유 → 무료 유입. (이미 `/share` 밈 카드 엔진이 숨겨져 있음. 실명·금액 노출 없는 형태로만.)
- **카카오 챗봇 "주간 리포트" 명령**: 알림톡(건당 8~13원)·브랜드메시지(25~53원)로 밀어 보내면 사용자 수에 비례해 돈이 나갑니다. **보내지 말고, 사용자가 물으면 답하는 방식(무료)** 으로. 웹 푸시(VAPID)는 무료라 추후 검토.
- **공개 콘텐츠 쪽(SEO)**: 절약 가이드·카드 실적 관리법 같은 글은 공개 페이지라 AdSense 가 바로 붙고 검색 유입도 만듭니다. 현재 공개 14쪽은 설명서 위주라 글 수를 늘릴 가치가 있습니다.

## 3. 관제가 "제대로 안 되는" 이유와 고칠 것

코드 분석 결과(관제 Worker `monitoring/`, 앱 `runtime/ops-monitor.js`)입니다. 요금제를 올려도 이 문제들은 해결되지 않습니다.

| # | 증상 | 원인(코드) | 고치는 방법 | 비용 |
|---|---|---|---|---|
| 1 | **알림이 아무 데도 안 옴** | 경고는 관리자가 `/ops-monitor`를 열 때 `summary()`에서만 계산. cron 은 수집만 함. 이메일·웹훅·카카오 전송 코드가 없음 | cron 끝에 `summary()`를 돌리고 새 critical/upgrade 경고를 **Cloudflare Email Workers(`send_email` 바인딩, 무료, Email Routing 이 이미 있음)** 로 1회 발송(중복 방지 키를 D1 `settings`에) | 0 |
| 2 | 대시보드가 거의 다 "확인 불가" | 요금제 등록이 7일 뒤 만료(`PLAN_VERIFIED_AT` 2026-10-01, `CF_PLAN` 변수 없음) → 10-08 부터 모든 한도가 null | `monitoring/wrangler.jsonc`에 `CF_PLAN`, 만료돼도 마지막 한도를 유지하고 "재확인 필요"만 표시 | 0 |
| 3 | 과거 오류를 못 봄 | 운영 이벤트는 인스턴스 메모리 220개뿐. 배포·재시작마다 사라짐. Workers Logs 꺼져 있음 | 앱·관제 둘 다 **Workers Logs 켜기**(대시보드, 무료 20만건/일·3일, Paid 7일). 이벤트 종류를 D1 telemetry 에 같이 남기기 | 0 |
| 4 | 외부에서 아무도 안 봄 | `monitoring/external-check.workflow.yml`은 템플릿만, 외부 감시 서비스 없음 | `.github/workflows/monitoring.yml`로 복사(공개 저장소라 무료, `*/30`), 실패 시 GitHub 이메일. 무료 상태감시(UptimeRobot·Better Stack 등) 1개에 `/health`·`/ready` 등록 | 0 |
| 5 | cron 실패가 안 보임 | `scheduled()` 실패는 메모리 이벤트 + throw. 5가계부 초과면 매일 "partial" 로 throw(소음) | `logWorkerError`로 로그 남기고 partial 은 실패로 던지지 않기 | 0 |
| 6 | 카카오 저장 실패가 "성공"으로 집계 | `nluOutcomeFromKakaoResponse`가 실패 문구를 못 알아봄 | 정규식에 실패 문구 추가 | 0 |
| 7 | 분석 토큰 만료를 모름 | `CF_ANALYTICS_TOKEN` 만료일 기록·검사 없음 | 시간마다 `/user/tokens/verify`, 30일 전 경고 | 0 |

**출시 전 최소(모두 무료, 반나절):** 1·2·4 + Workers Logs 켜기. 이 네 가지면 "서비스가 죽었는데 모른다"와 "한도가 찼는데 모른다"는 없어집니다. 코드 변경은 V22.9.37 에 넣고, 관제 Worker 는 사용자가 `npx wrangler deploy --config monitoring/wrangler.jsonc`로 배포합니다(새 `send_email` 바인딩과 수신 주소 변수 필요 → 별도 승인).
