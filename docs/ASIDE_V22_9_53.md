# V22.9.53 남은 수동 확인

로컬 합성 서버와 데스크톱 Chrome 검사에서 확인한 DOM 상태를 실제 보조기기의 발화 결과로 간주하지 않습니다. 기존 [V52 수동 확인](ASIDE_V22_9_52.md)과 이전 버전의 미확인 항목을 유지합니다.

- iOS Safari·Android Chrome·카카오톡 인앱에서 두 예산 폼의 실제 숫자 키보드·한글 조합·선택 치환·커서·초점을 확인합니다.
- 실제 OS 클립보드로 정상·잘못된 금액을 붙여넣고 원문과 유효성·저장 금액을 확인합니다.
- VoiceOver·TalkBack에서 입력 직후 금액 가리기, 안내 후 가리기, 다른 탭의 가리기, 해제 후 새 입력을 확인합니다. D 자동 합계 안내는 숨김 중 일반 문구로 바뀌어야 하며 행 번호·20억원·200행 등 오류 설명은 유지되어야 합니다. 기존 E의 보조기기 금액 읽기 허용 정책은 그대로입니다.
- 실제 BFCache의 `persisted=true` 복원을 확인합니다. 합성 pagehide/pageshow 호출과 실제 재진입은 cache-hit의 증거가 아닙니다. 개인 HTML의 `no-store`를 완화하지 않습니다.
- 별도 승인으로 운영에 적용할 경우 실제 Workers Web Crypto·기존 잠금·교체 RPC와 두 관리자 간 충돌을 확인합니다. 구형 p1 폼은 거절되며, 입력을 보존한 상태에서 최신 저장 계획을 명시적으로 열어 비교해야 합니다.

이번 로컬 작업은 운영 적용이나 외부 설정 변경을 포함하지 않습니다.
