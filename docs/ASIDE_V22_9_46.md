# V22.9.46 사용자 배포와 실기기 확인 절차

`V22.9.46-LUCIAN-E`는 PR #79의 긴급 수정과 Lucian 묶음 E를 포함합니다. 이번 작업에서 운영 배포·SQL·Secret·바인딩·콘솔 변경을 수행하지 않았습니다. 배포에는 기존 앱 Worker만 필요합니다.

## 1. 배포할 커밋 확인

PR의 Ubuntu·Windows × 일반·분류 표 부재 CI를 확인하고 PR을 병합합니다. 깨끗한 main에서 다음 검사를 실행하고 `VERIFICATION_V22_9_46.md`의 판 번호·검사 수·체크섬 수·소스 SHA-256과 대조합니다.

```powershell
node .codex/scripts/verify-repository.mjs
npm run validate:categories-absent
git diff --check
```

## 2. 업로드·대조·승격

기존 `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` 또는 `CF_ACCOUNT_ID`를 사용자가 자신의 환경에서 설정합니다. 토큰을 명령 인자나 Git에 기록하지 않습니다.

```powershell
node tools/deploy-worker-version.mjs
```

새 버전 ID와 `output/deploy/V22.9.46-LUCIAN-E/`의 대조 기록을 확인합니다. 마지막 문서상 운영 기준은 V22.9.44 버전 `3d12b754-299f-4e83-8235-c5994d7fa4f9`, 배포 `4d5884dd-1a12-408a-93b9-d934e6c71bae`입니다. 업로드 직전 실제 운영 버전·바인딩을 확인하여 되돌리기 기준으로 기록합니다. V22.9.45를 먼저 배포했으면 그 기준을 사용합니다.

업로드 이후 배포·Secret·바인딩이 바뀌지 않았는지 대조합니다. G-4가 남아 있으므로 상태가 달라지면 최신 상태에서 업로드·대조를 다시 수행합니다. 확인한 새 버전을 사용자가 승격합니다.

```powershell
node tools/deploy-worker-version.mjs --promote <새_버전_ID>
```

승격 뒤 소스 SHA-256, `/health` 5회 연속 판 일치, `/ready`와 공개 검사를 확인합니다. 되돌려야 할 때는 업로드 직전 기록한 실제 운영 버전 ID로 실행합니다.

```powershell
node tools/deploy-worker-version.mjs --rollback <배포_직전_운영_버전_ID>
```

## 3. 실기기 확인

iOS Safari·Android Chrome·카카오톡 인앱 브라우저에서 각각 확인합니다. 밝은 화면과 어두운 화면, 모션 줄이기 설정을 함께 확인합니다.

1. 가계부가 없는 계정의 시작 화면에서 우리집 생활비·여행·모임 정산·단발성 네 템플릿을 확인합니다. 링크를 눌렀을 때 생성 완료 표시 없이 기존 이름 확인 폼으로 이동하고, 폼 제출 뒤 서버 응답으로 생성되는지 확인합니다.
2. 이름 있는 새 가계부의 첫 기록 버튼으로 빠른 입력을 엽니다. 전체 기간에 기록이 있는 가계부의 빈 달에는 빈 폴더가 표시되지 않아야 합니다. 조회 실패 때도 새 가계부로 표시하지 않아야 합니다.
3. 생성 후 24시간 이내의 기록 없는 가계부에 처음 들어가면 투어가 표시됩니다. 다음·건너뛰기·Esc, 화면 회전, 빠른 입력 열기를 확인합니다. 두 번째 방문에는 표시되지 않아야 합니다. 늦게 첫 방문했거나 다시 보려면 기존 월·가계부 쿼리에 `tour=1`을 추가합니다. 기존 가계부에는 자동 표시하지 않습니다.
4. 상단 눈 아이콘과 전체 메뉴의 외관 설정에서 금액 가리기를 켭니다. 첫 화면부터 금액이 가려지고 새로고침 뒤에도 유지되는지 확인합니다. 큰 예산 숫자, 하루 금액, 거래, 날짜 상세, 목표·정산 화면을 확인합니다. 입력칸과 캘린더 날짜는 보여야 합니다.
5. 가려진 금액을 누르면 그 금액만 3초 보인 뒤 다시 가려져야 합니다. 거래 수정 창이 함께 열리지 않아야 합니다. 뒤로 가기·앞으로 가기 뒤에도 토글이 작동해야 합니다. 끄면 즉시 모두 보이고 서버에 저장 요청이 발생하지 않아야 합니다. 화면에서만 가리므로 보조기기는 원래 금액을 읽습니다.
6. 실제 서버 결과로 챌린지·목표 달성을 확인하고, 기록과 예산이 있는 지난달의 예산 준수를 확인합니다. 각 사건은 기기에서 한 번만 축하해야 합니다. 목표 납입 직후 임시 화면, 되돌리기, 요청 대기·실패에서는 축하하지 않아야 합니다. 모션 줄이기에서는 배지만 표시합니다.

기기 localStorage를 삭제하거나 차단하면 완료 이력과 가리기 설정이 유지되지 않습니다. 월 예산 축하는 종료된 달의 합계 확인이며 별도 회계 마감 기능이 아닙니다.
