### 1. 재개 대상과 실행 환경을 확인해 주세요

- 새 실행 식별자 `S=YYYYMMDD-HHmm`을 KST로 정하되, 기존 가계부 `V22938 점검 20261010-2311`을 이어서 사용하세요. 이름은 V38이어도 검사 버전은 `/health`의 실제 응답으로 판단하세요. 별도 실행 `20261010-2244`와 혼동하지 마세요.
- `/health`에서 `V22.9.39-PUBLIC-GUIDES`와 정상 상태를 확인하세요. 시작·종료, 긴 중단 후 재개와 각 쓰기 묶음 직전에 버전을 확인하세요. 다른 버전이면 남은 V39 항목을 BLOCKED로 남기고 버전·시각을 보고하세요. 자체 배포나 롤백으로 맞추지 마세요.
- A의 기존 테스트 계정으로 로그인하고, 가계부 이름과 실제 ID가 원래 비공개 `2311` 실행 기록의 대상과 같은지 확인하세요. 이 ID를 H라고 부릅니다. 이름이나 합계만으로 H를 추정하지 마세요. `2244`용 재개 파일을 대신 사용하지 마세요.

- 사용자가 쓰는 일반 프로필을 사용하도록 이미 승인했다면 그 범위에서 진행하되, 독립 세션 검증으로 기록하지 마세요. 이전 실행의 로그아웃 승인이 새 공유 프로필의 모든 세션 조작까지 허용한다고 해석하지 마세요. 필요한 확인은 대상과 영향을 구체적으로 설명하고, 이미 받은 같은 범위의 승인을 반복해서 묻지 마세요.
- 테스트 범위는 H와 지정한 합성 자료뿐입니다. 실제 사용자 가계부, SQL·직접 DB/API 쓰기, 계정 연결·통합, 운영 배포·롤백·Cron·환경변수·Secrets·외부 콘솔 설정은 이 절차에 포함하지 않습니다.

P4b·P4c의 준비는 P3 이후 B가 아직 구성원일 때 수행합니다. B의 같은 세션에서 두 탭을 열어 정상 UI로만 거래 폼과 기존 카드의 목표 폼을 준비하세요. 거래 폼에는 날짜 `2026-10-11`, 지출 800원·현금·기타지출·B·내용 `V39QA-S-B-DENY`를 입력하고, 목표 폼에는 5,000원을 입력하되 아직 제출하지 마세요. 그런 다음 A가 B를 조회 전용으로 바꾸고 B의 별도 새 탭에서 역할을 확인합니다. 이 과정에서 A/B의 세션 구분을 바꾸지 않습니다.

P4b·P4c는 역할 변경 전에 받은 정상 폼을 한 번씩 제출하는 시험입니다. 유효한 입력이 서버까지 전달되어 권한 거절 안내가 반환되고, 새 조회의 데이터도 보존된 경우에만 해당 경로를 `PASS-PC(서버 거절)`로 기록하세요. 브라우저가 제출을 막았거나 폼이 자동 갱신되어 제출할 수 없으면 그 서버 경로는 NOT-RUN입니다. 세션 만료·CSRF 오류·통신 실패를 조회 전용 권한 검사 통과로 세지 마세요.

버튼 숨김은 별도의 `PASS-PC(UI)`입니다. 일부 폼의 거절을 모든 서버 경로의 권한 통과로 확대하지 마세요. DOM·요청 변조, 직접 API 호출, 다른 사용자의 거래 수정 시도로 범위를 넓히지 마세요. 새 조회 화면에 예상과 다르게 쓰기 UI가 노출되면 제출하지 말고 FAIL로 기록하세요. P4b·P4c에서 예기치 않게 저장됐다면 다음 쓰기를 중단하고 정확한 거래·목표·합계·역할을 보고하세요. 자동 삭제·초기화로 실패 증거를 없애지 마세요.

- Q4를 만들려고 브라우저 보안 정책·권한을 임의로 변경하거나 API를 교체하지 마세요. 준비된 거절 환경이 없으면 NOT-RUN입니다. 거절 상황의 검증과 성공 상황의 클립보드 줄바꿈 검증을 별도로 기록하세요. 단행 입력에 붙여넣은 결과는 줄바꿈 보존의 증거가 아닙니다.

### 5. 실기기·카카오 확인 조건을 구분해 주세요

카카오는 이전에 코드 검증으로 진행하기로 했습니다. 이번 후속 문서만으로 실사용 계정 연결·참여나 메시지 발송을 시작하지 마세요. 실환경 검증이 별도로 요청되고 테스트 계정·방과 대상 H가 확인되었을 때 전용 절차를 준비합니다. 기존 로컬 카카오 135개 단언의 통과를 실제 공급자·메시지 전달·V39 실환경 PASS로 옮기지 마세요.

| ID | 필요한 환경 | 남겨야 할 결과 |
| --- | --- | --- |
| D1 | 실제 iPhone Safari / Android Chrome | 기기별 로그인·새로고침·로그아웃 후 보호 페이지 재접속을 분리해 기록합니다. |
| D2 | 실제 카카오 인앱·외부 브라우저 | 실환경 시험이 요청된 경우 H 유지와 필요한 재인증 안내를 확인합니다. 브라우저가 바뀌면 자동 로그인된다고 가정하지 않습니다. |
| D3 | 실제 터치·한국어 키보드 | 조합 입력, 날짜·금액, 버튼 가림, 뜻하지 않은 제출과 중복 저장을 확인합니다. |
| D4 | 실제 기기의 세로·가로·확대·라이트/다크 | 리포트·메뉴·예산과 준비된 정기 화면의 잘림·넘침·하단 조작 겹침을 확인합니다. |

### 6. 종료와 보존을 확인해 주세요

- 새 GET으로 두 달·경계 주의 합계, 원래 네 거래, 후속 B 거래의 유무, 카드 수·사용액·목표, 참여자 역할과 정기 항목을 대조하세요. P3가 미실행이면 2절 값, 성공했으면 3절의 증가한 값이 기준입니다. 다른 시험에서 별도로 승인된 쓰기가 있었다면 그 증감을 따로 더해 계산하세요.
- Q1이 끝났으면 기존 카드 목표는 없음이어야 합니다. P5가 끝났으면 A 소유자·B 구성원이 최종 상태입니다. 누락된 복원은 성공으로 표시하지 말고 정확한 잔존 상태를 보고하세요. 새 초대·참여 이력을 자동 삭제하지 마세요.
- 테스트 거래·카드·가계부·A/B 계정을 보존하세요. 이미 삭제된 DELETE를 재생성하지 않으며 추가 삭제나 계정 통합을 하지 마세요.
- 독립 테스트 세션은 승인된 종료 범위에 따라 로그아웃하고 새 보호 GET이 로그인 화면인지 확인하세요. 공유 프로필이라면 영향을 받는 세션과 이미 받은 승인의 범위를 확인한 뒤 진행하세요. 다른 사용자 탭이나 입력 중인 창을 임의로 닫지 마세요.
- 새 문서를 `docs/deployments/V22_9_39_QA_FOLLOWUP_<날짜>_<시각>.md` 형태로 저장하세요. 결과에는 실제 버전·KST 시각·항목 ID·실행 주체·환경·기대값·재조회값·잔존 상태를 적으세요. 이전 기록을 덮어쓰거나 V38의 BLOCKED를 V39의 PASS로 바꾸지 마세요.
- 공개 기록에는 실제 계정명·가계부 ID·초대코드·인증 코드·비밀번호·개인정보·실사용 금융 자료를 넣지 마세요. 민감정보가 없는 합성 테스트 명칭·금액과 판정만 적고, 비공개 증거는 Git 밖에 보관하세요. 커밋·푸시 범위는 해당 실행에서 합의한 지시를 따르세요.

### 7. 판정과 중단 기준

`PASS`는 명시한 환경·경로·기대값을 실제 실행하고 재조회한 경우에만 사용합니다. `FAIL`은 실행 결과가 기대값과 다른 경우, `NOT-RUN`은 준비된 환경이나 대상이 없어 실행하지 않은 경우, `BLOCKED`는 시작한 절차가 버전 변경 등으로 계속될 수 없는 경우입니다. 부분 통과는 하위 항목만 PASS로 기록하고 전체 완료로 합산하지 마세요.

다른 가계부의 자료, 예상하지 않은 참여자·권한, 합계 불일치, 필수 조회 실패, 잘못된 쓰기 또는 버전 변경을 발견하면 관련 쓰기를 즉시 중단하세요. 첫 실패와 마지막 확정 성공 단계를 남기고 자동 복구·삭제·재배포를 시도하지 마세요. HTTP 200만으로 성공을 판단하지 말고 실제 화면과 조회 결과를 확인하세요.

